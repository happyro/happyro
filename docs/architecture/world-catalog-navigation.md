# 世界图鉴与导航架构

## 目的

HappyRO 在游戏内提供两个面向世界资料的入口：

- 右上角导航：快速搜索目标、查看路线并执行允许的操作；
- 冒险工具：通过 NPC、魔物和地图图鉴浏览详情并执行相同的寻路、传送或召唤操作。

两个入口共享底层实体模型和业务操作，但不强求展示相同数量的记录。导航需要保留官方路线节点，图鉴则应表达真实的游戏内容，不能把官方导航表中的辅助节点误认为服务器实体。

## 数据来源与权威边界

### NPC

NPC 图鉴以 `repos/happyro-server/npc/**/*.txt` 中的服务器 NPC 实例为完整来源。客户端脚本 `repos/happyro-client/scripts/generate-world-catalog-assets.mjs` 解析这些定义，并结合 `src/DB/NpcNameTranslations.zh-CN.json` 生成：

- `src/DB/Navigation/NpcInstanceNameTable.js`：服务器 NPC 的地图、坐标、中文名称及源名称索引；
- `applications/pwa/data/world/npc-assets.json` 和 NPC 图集：客户端可用的外观资源。

官方 `navi_npc_krpri.lub` 不是 NPC 存在性的权威来源。它用于补充导航 ID、NPC Class、官方名称、别名、路线位置等导航身份。服务器实例即使没有匹配的官方导航记录，也应保留在 NPC 图鉴中；此类记录显示为静态资料，在取得可验证的实时身份前不开放“传送到 NPC 附近”。

### 魔物

魔物图鉴的属性、掉落和常驻刷新地图来自服务器数据库与刷新配置，客户端官方魔物资料用于补充名称和导航信息，客户端资源用于展示图片。

导航里的魔物记录只说明客户端已知的导航分布，不代表某只魔物当前存在。召唤权限、Boss/MVP 限制、地图规则和实际生成结果始终由 map-server 判断。当前地图传送只定位到所选刷新地图，不承诺定位到某个实时魔物实体。

### 地图

地图目录合并客户端世界地图、地图信息、图片和 GAT 资源。地图图片或 GAT 缺失只影响预览和寻路能力，不应决定地图实体是否存在。服务器负责判断目标地图是否已加载、角色能否进入、地图是否禁止传送以及目标坐标是否合法。

## 图像资源生成与加载

三类图像均以官方客户端资源为只读源，由离线工具生成运行时产物；后台和游戏端不在请求或渲染期间转换 BMP。

- 物品：根仓库 `tools/resources/catalog/main.py items images` 将资源映射中的官方 BMP 生成透明 PNG，输出到 `work/game-data/items/kro-20211105/icons/` 和 `illustrations/`。后台按物品 ID读取 PNG，游戏端按需请求列表图标和选中物品的详情图。
- NPC：后台保留预生成的 NPC PNG；客户端构建脚本 `scripts/generate-world-catalog-assets.mjs` 将 NPC PNG 合成为 WebP 图集，并通过 `npc-assets.json` 的图集坐标显示。游戏端不逐个请求 NPC 图片。
- 地图：后台保留有效地图 PNG，客户端按需读取当前列表可见的地图图片；选中地图时另外读取对应 GAT，用于坐标换算、缩略预览和当前地图寻路。没有真实图片时只使用 GAT 预览。

资源产物与客户端资源版本绑定。重新生成图片后，服务端图片 URL 携带生成版本，避免浏览器继续使用旧缓存；生成目录属于运行时产物，不提交到 Git。

## 统一世界实体模型

客户端通过 `WorldCatalogService.js` 将不同来源转换为统一实体。当前核心类型为：

- `NPC`：可与服务器 NPC 身份关联的实例；
- `MOB`：魔物资料与分布目标；
- `MAP`：地图目标；
- `WARP`：地图连接或官方导航辅助节点。

实体统一提供规范化的 `mapName`、坐标、确定性组合键、资料来源、静态能力和运行时可用状态。能力字段描述该实体理论上支持哪些操作，例如寻路、地图传送、NPC 传送或召唤；它不是权限凭证，不能替代服务器校验。

官方 `Navi_Npc` 中 `npcClass=99999` 的地图连接记录会归类为 `WARP`。它可参与路线规划，但不会进入 NPC 图鉴，也不会显示 NPC 传送操作。

## 两个入口的职责

### 右上角导航

导航可以显示更广的目标范围，包括地图、魔物、真实 NPC、服务节点和 Warp。搜索结果立即展示，NPC 实时状态随后异步更新为“校验中”“可用”或“当前不可用”。服务器不可用或校验超时不应删除静态搜索结果。

### 冒险工具图鉴

- NPC 图鉴展示服务器实例目录，使用官方导航增强匹配到的实例；
- 魔物图鉴展示属性、掉落、刷新地图，并提供受权限控制的召唤；
- 地图图鉴展示地图图片或 GAT 预览，并允许在地图上选择坐标。

无图片的 NPC 或地图使用占位或 GAT 预览，不因客户端资源缺失而从图鉴消失。纯导航 Warp 和内部路线节点不进入 NPC 图鉴。

## 交互与服务器校验

寻路、地图传送、NPC 传送和魔物召唤由共享服务维护状态，两个入口不应各自复制权限、冷却和错误处理。

### 寻路

自动行走只在角色当前地图执行。跨地图路线可以展示下一段 Warp 或传送服务节点，但客户端不会假定已经完成跨图交互。缺少 GAT 或找不到路径时，寻路按钮应禁用或明确显示不可用原因。

### 地图传送

地图传送使用 HappyRO 专用封包：

- `0xd00`：客户端提交请求 ID、地图和坐标；
- `0xd01`：服务器返回结果、实际地图坐标和剩余冷却。

map-server 校验账号权限、跨地图策略、地图加载状态、进入限制、地图禁传规则、坐标范围和冷却。客户端只有收到成功结果后才开始冷却；失败时两个入口显示相同的结构化原因。

### NPC 传送

搜索结果展示前可批量查询 NPC 可用性，执行传送时服务器再次校验。当前实时身份使用地图、坐标容差和 NPC Class 匹配，并排除隐藏、隐身或对角色不可见的 NPC。服务器寻找 NPC 附近的安全落点后传送角色。

没有官方导航身份的服务器 NPC 仍可查看和寻路，但不能仅凭静态坐标执行 NPC 传送。未来如需扩大可传送范围，应在生成阶段为服务器 NPC 建立稳定实例 ID，并让服务器按该 ID 解析实体，而不是放宽客户端坐标匹配。

### 魔物召唤

客户端只提交魔物 ID。服务器负责校验召唤策略、账号能力、冷却、Boss/MVP 开关、地图规则和角色附近的生成位置。导航资料或图鉴资料本身不授予召唤能力。

## 数据重放

导航 LUB 的静态快照、NavigationCatalog、NavigationGraph 及其加载时序统一记录在[客户端静态运行数据与 Lua 生命周期](client-static-runtime-data.md)。

静态目录可以由固定输入重新生成：

```bash
cd repos/happyro-client
npm run catalog:world
npm run catalog:monsters
npm run build:pwa
```

相同的服务器 NPC/魔物配置、中文词库、官方导航文件和客户端资源应生成等价的目录。生成清单记录资源哈希，用于发现输入变化。

以下状态不能由静态目录重放，必须使用真实 map-server 或测试夹具验证：

- NPC 是否已经加载、隐藏或满足任务条件；
- 地图是否开放以及副本/分流是否存在；
- 角色位置、权限和传送冷却；
- 魔物当前刷新状态和召唤结果。

## 修改约束

后续修改应遵守以下原则：

1. 不把客户端导航数据当成服务器实体存在性的证明；
2. 不因缺少图片或 GAT 删除真实实体；
3. 不在视图组件中重复实现传送、寻路、召唤或冷却规则；
4. 新增可执行操作必须由服务器返回结构化结果；
5. 同一实体在导航和图鉴中的名称、地图、坐标及状态语义必须一致；
6. 修改数据生成逻辑后，必须重新生成目录并执行客户端测试、构建及真实浏览器验收；
7. 修改传送或召唤协议后，必须同时验证 Client 与 Server 的封包编号、长度、注册和运行时响应。
