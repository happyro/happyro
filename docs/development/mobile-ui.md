# 移动端 UI 开发与验收

布局与组件接入规则以客户端的[菜单布局](../../repos/happyro-client/docs/mobile-menu-layout.md)为准；登录与恢复见[连接恢复](../../repos/happyro-client/docs/connection-recovery.md)。根仓库只维护跨端验收边界，不复制组件尺寸、设备断点或已完成批次。

## 开发约束

- 手机横竖屏、平板、分屏均按实际可用空间布局；密度、方向和内容宽度分别判断，沿用共享布局组件。
- 触控流程不依赖右键、悬停或拖放；面板阻止误触地面，旋转保留业务草稿，关闭释放监听和迟到回包。
- 金额、物品身份、目标、权限和最终结果以服务端为准；等待期间防重复提交，不重放断线前的交易或技能操作。
- 桌面鼠标、键盘与焦点行为必须回归；模拟视口、组件测试、实服交互和真机分别记录，不能互相替代。

## 待核验范围

以下是尚需确认的覆盖边界，不代表全部存在缺陷，也不沿用旧批次的开发顺序。

- 移动端自动拾取列表截断、翻页跳顶和真实滑动手感的用户反馈。
- iOS/Android 后台冻结、锁屏、系统回收页面与恢复行为；屏幕常亮受浏览器和系统策略影响。
- 真机软键盘、横竖屏切换、平板分屏、多指移动与技能操作、浮层和长内容。
- 双方交易、摆摊、商店、邮件附件、银行、仓库容量/重量、宠物进化等真实消耗场景。
- 伴侣指定攻击/移动、技能详情与状态同步；低频商城/奖励、验证码、装备比较及聊天室窗口按实际可达性复查。
- 冒险工具自动寻路仅支持当前地图；跨地图路线预览不等于自动完成跨图交互，需分别验收寻路、停止和传送。自动战斗不支持全地图巡逻。

当前发行包统一使用[发布验收清单](../operations/release-checklist.md)，只把实际执行过的范围标为通过。复现、截图和日志放在 work/ 或 artifacts/，产品行为变化写入对应仓库 changelog。


## 菜单样式维护

移动菜单已按公共框架、具体菜单布局、底部标签、普通表单和弹窗输入分开维护。底栏使用显式的 `menu-footer`，内部按钮组不再按菜单类名推断底栏身份；与输入关联的按钮保留在表单行。手机竖屏采用上下布局，手机横屏和平板共用横向布局规则。

具体文件职责、加载顺序、公共角色和新增菜单接入方法见客户端仓库 `docs/mobile-menu-layout.md` 的「样式职责与复用」。更改布局时清理已替代规则，避免在公共文件中不断追加具体菜单的覆盖样式。

菜单布局使用公共 `data-menu-arrangement`：手机竖屏为 `stacked`，手机横屏和平板横竖屏为 `wide`。真实 `data-orientation` 控制窗口高度、通知避让和键盘位置；平板竖屏标准窗口使用可用区域的 72% 高度，控件密度与横屏一致。

平板按钮的宽度、文字留白与居中统一由客户端 `MenuButtonSizing.css` 管理，按普通操作、导航、分页及数量步进分类，HUD 与冒险工具共享。业务布局保留等分等必要例外，手机和桌面端不套用平板尺寸。

平板游戏 HUD 与菜单共用 `data-menu-arrangement`，横竖屏均采用 `wide`：状态区、小地图和聊天预览保持横向规则；真实方向继续用于窗口高度和通知避让。点数框、列表边框、宠物进化提示与操作行、商店金额格式和摊位状态文案在手机／平板共用，控件尺寸仍按密度区分。
