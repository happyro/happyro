# 地图加载失败恢复

当前实现不增加客户端资源预检。普通传送仍直接进入目标地图；只在资源加载失败或超时后恢复。出生点继续统一为经典修炼场，不增加分流。

## 用户行为

| 场景 | 行为 |
| --- | --- |
| 必需 RSW/GND/GAT 缺失、解析或初始化失败 | 自动请求返回最近成功进入的位置 |
| 无可用原位置、或返回原位置后再次失败 | 自动返回普隆德拉卡普拉旁 |
| 登录时加载已保存的坏地图 | 使用同样恢复流程，不需要先进入场景 |
| 加载超过 30 秒但尚无明确失败 | 提供“重试加载”“返回普隆德拉”“退出游戏”，不强制移动 |
| 普隆德拉也失败或超时 | 停止自动移动，只提供重试和退出 |
| 恢复请求 10 秒没有新地图开始 | 明确提示恢复超时，可重试加载或退出，不自动重复请求 |

固定安全位置选择普隆德拉卡普拉旁的 `prontera,148,87`，由服务端寻找附近可行走且非传送门的格子。原位置也是服务端记录，客户端不能指定恢复坐标。音乐、装饰纹理等原有可选资源缺失不触发整图恢复。

## 实现边界

- 每次登录／传送发送服务端生成的加载编号；只有当前尚未成功确认的加载允许恢复，旧编号及已成功进入地图的请求被拒绝。
- 当前成功位置、未完成标记及恢复阶段持久化在角色变量中，断线重登保留恢复预算；新角色无记录时直接采用固定安全点，不做历史数据迁移。
- 资源加载完成、角色界面初始化和渲染启动后才发送成功确认。安全点也失败时不会因重登重新开始无限自动恢复。
- 客户端取消旧 worker 加载，隔离旧 generation 的场景数据、图片回调、完成确认和错误回调。点击“返回普隆德拉”前也取消仍在进行的加载。
- “重试加载”只重新加载当前目标，不重放 NPC 对话、扣款、物品交付或传送业务。
- 恢复不会撤销已经完成的任务扣款或材料交付，也不会重置背包、职业及任务进度。

封包：客户端 `0x0d0c`（加载编号与恢复动作），服务端 `0x0d0d`（加载上下文）、`0x0d0e`（恢复结果）。恢复请求在角色尚未完成地图加载时可处理，不依赖已出现的角色实体。

## 验收

客户端全量 1,917 项测试通过（300 个文件通过、1 个跳过）；服务端 18 项策略断言及入站表上限／封包布局编译期断言通过，map-server 编译成功。无头测试使用普通账号，模拟 HTTP 404、损坏地图文件及一直不返回的下载，不修改真实资源、不伪造任务或角色职业。详见本目录证据。
