## 2026-09-23：阶段 1 实现记录

### 本轮范围

- `UI/Game/GamePresentation.js` 在地图 UI 装配区选择桌面／移动展示；桌面保持原组件 append 行为，移动端挂载独立 `MobileGameHUD`，保留实体手柄模块。
- `UI/Mobile/game/` 提供独立横屏布局与 DOM 视图，读取 Session 角色信息；人物、状态、地图、菜单和聊天面板可打开／关闭，菜单可以确认返回选角。
- 小地图按真实 Altitude 可行走格和水面绘制网格，标记人物位置，可展开。当前不是桌面小地图图片及其全部标记的移植。
- 状态区显示最多四个已加载的真实状态图标和总数，点击可查看所有状态说明与剩余时间。
- `UI/Game/ChatFeed.js` 接入现有聊天消息产生点，保存最近 80 条，不读取隐藏桌面 DOM；公开消息输入调用既有发送入口，不复制封包构造逻辑。
- 预留左下固定摇杆、右下攻击和三个技能槽位，暂不绑定战斗或移动操作；三个槽位仅为当前骨架排版，不是最终数量决定。菜单中的背包、装备、技能、任务、社交入口暂时禁用。
- 移动 HUD 阻断触摸、鼠标和键盘事件向场景传播；打开面板取消未完成的地图触摸／行走输入并管理模态冻结；跟随 visualViewport 调整显示区域。
- 换图通过现有 UIManager 移除生命周期清理计时器、订阅、监听器和模态状态；断线主动移除 HUD。重复挂载只保留一组更新循环和订阅。
- 旧 MobileUI 在新移动模式下不显示，也不能被首次触摸或旧快捷入口重新唤起；鼠标主导的桌面模式仍保留原行为。

### 验证证据

- 7 个相关测试文件、23 个测试通过：新增 HUD 视图、装配分流和生命周期测试，及既有方向遮罩、实体手柄和移动弹窗测试。
- 修改的 JavaScript 通过定向 ESLint 检查。
- Chromium 实际登录进入地图，面板开关、844×390／667×375／568×320 主区域边界、返回选角后重新进入通过，没有页面异常。
- 本机 WebKit 同样通过上述流程；面板操作期间未观察到移动或攻击请求。
- 补测模拟 visualViewport 高度降为 180px：发现并修正聊天输入区被消息列表挤出面板的问题，消息列表改为可收缩区域，输入与发送保留在可见范围。该检查是视口模拟，不是真实手机软键盘验收。
- 桌面实际登录后仍显示 BasicInfo、MiniMap、ChatBox 和原快捷栏，不挂载 MobileGameHUD；用可见顶部区域拖动窗口成功。早先脚本选中了收起窗口中的隐藏元素，修正测试定位后通过。
- 本机截图／报告位于 `artifacts/mobile-game-landscape.png`、`artifacts/mobile-game-webkit.png`、`artifacts/mobile-game-desktop.png` 及相应 JSON；这些是本地验收产物，不随文档提交。
- 已执行完整 `--all` PWA 构建，运行产物核对以 `scripts/client/refresh-client.sh verify --no-color` 的本轮输出为准。

### 限制与下一步

- 需要用户在 iPhone 上确认首屏位置、尺寸、安全区、面板滚动与真实软键盘表现；本机 WebKit 不能替代这项确认。
- 本轮桌面验证覆盖首屏装配与窗口拖动，不代表所有物品、技能、NPC 等业务交互已经全面回归。
- 未适配业务模块仍保留 prepare 和原封包回调；其数据与桌面组件的耦合将在对应阶段拆分。本轮没有将隐藏桌面 DOM 作为新人物、地图或聊天展示的数据源。
- 阶段 2 接入实际摇杆、攻击及多指控制；后续技能槽位配置和施法流程属于阶段 4。NPC 等按需打开的旧业务窗口尚未重构。
