这些不阻塞文档记录；在相关功能实现前确认或给出可审阅的具体设计。

## 2026-09-23：阶段 2 核心操作

### 本轮范围与操作约定

- `PointerControls` 使用原生 Pointer Events。左摇杆和右攻击分别保存 pointerId，捕获各自触点，处理 pointerup／pointercancel／lostpointercapture；右手释放不会取消左手。
- 摇杆中心有死区、位移限幅；方向按镜头朝向转换，复用 MapControl 的空格检查，每 200ms 请求前方短距离移动。松手停止继续发移动请求；服务端已接受的最后一段短距离仍可能走完，不宣称角色立即定格。
- 点场景保留点地走路，点实体只选择并显示目标；怪物按住攻击、松手取消连续攻击及延迟到达动作，无目标不自动选怪。移动优先于追击：摇杆移动中仅尝试范围内攻击，不自动改变摇杆方向追怪。
- 选中 NPC、地面物品、传送点分别提供“交谈”“拾取”“进入”按钮，复用原业务。NPC 后续对话窗口仍属于阶段 5，本轮并未重构全部 NPC 面板。
- 菜单新增镜头面板，提供旋转、俯仰、缩放和重置按钮，不需要右键或双指拖动。
- `UI/Game/GameCommands` 负责业务桥接，控件只传递方向和操作意图；EntityControl 的 onFocus 增加显式选择／攻击及是否允许追赶参数，默认调用仍保留桌面语义。
- `AttackIntent` 防止迟到的“目标太远”响应在松手或换目标后重新发起触摸攻击；桌面鼠标及实体手柄攻击接管时清除触摸请求归属。实体手柄组件和原鼠标事件路径保留。
- 移动场景由独立 Pointer 控制器接管；旧 Core/Mobile 游戏触摸转鼠标／双指镜头路径不再同时处理它。新控制器只在移动 HUD 生命周期挂载，桌面不挂载。
- 打开面板、失焦、切后台、旋转、死亡、换图、断线和退出清理触点／计时器／待执行动作；外部阻断面板通过 FreezeUI 在控制循环中取消输入。
