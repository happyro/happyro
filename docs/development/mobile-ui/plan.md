| 下方剩余区域 | 聊天摘要 | 显示少量消息，点击展开聊天面板；输入时适配键盘，避免遮挡发送和关闭按钮 |

布局按可用横屏宽高、安全区和浏览器工具栏适配；窗口固定布局，内容超出时内部滚动。首屏常驻区域优先保证场景可见和移动、攻击操作空间。

## 统一交互规则

| 桌面操作 | 移动端替代 |
| --- | --- |
| 右键查看详情或菜单 | 点击条目展开详情及操作按钮 |
| 悬停提示 | 点击查看，提供明确关闭方式 |
| 拖动物品装备、移动或交易 | 选中条目，再选择装备、存入、取出等操作及数量 |
| 拖技能或道具到快捷栏 | 点击槽位，选择内容；提供替换、清空操作 |
| 双击使用、装备或学习 | 明确的使用、装备、学习按钮 |
| 拖动、缩放窗口 | 固定面板布局及内部滚动 |
| 键盘快捷键、Esc | 可见入口、关闭或返回按钮 |

长按可作为后续辅助能力，但不得成为任何必要功能的唯一入口。手机主界面不以 F1、F2 等键名作为技能按钮。

移动摇杆与攻击必须允许双指同时操作。每个控件独立跟踪触点；离开地图、弹出阻断操作的面板、切到后台或出现横屏遮罩时，释放移动和攻击状态，避免持续移动或误攻击。

## 摇杆与技能按钮实现决策

2026-09-23 讨论确认：采用“新触摸控件 + 复用游戏业务”，以原生 Pointer Events 实现屏幕控制，当前不引入第三方摇杆库。

| 部分 | 实现方式 |
| --- | --- |
| 摇杆外观与布局 | 独立移动组件，适配固定横屏布局 |
| 按下、滑动、松开 | 重写旧 MobileUI 事件层；按 pointerId 独立跟踪触点，使用指针捕获 |
| 输入取消 | 统一处理 pointercancel、lostpointercapture、失焦、后台、弹窗、方向遮罩、换图和退出；取消应可重复调用 |
| 方向转换与可行走格检查 | 审查后提取复用现有算法，不连同旧 DOM 事件和计时器一起复制 |
| 移动、攻击和施法 | 调用共享业务接口，控件不直接构造封包，也不模拟桌面按键 |
| JoystickUI 实体手柄 | 保留，与新屏幕摇杆区分；不因移动重构删除桌面手柄能力 |

摇杆只输出移动方向；攻击按钮传递攻击意图与目标；技能槽位传递技能、等级及目标信息。业务层负责规则校验与网络操作。以后调整布局、增加槽位或替换摇杆控件，不需要重写游戏业务。

每个控件独立拥有触点：允许左手持续移动、右手点击攻击或技能，松开右手不能结束左侧摇杆输入。多指输入支持不代表绕过游戏本身的施法、移动和攻击限制。

NippleJS 可作为将来固定／浮动摇杆控件的候选，但它不负责本项目的移动发包、目标规则、旧地图事件隔离或场景生命周期。目前单固定摇杆的需求采用原生实现，避免为了一个控件新增依赖。

参考：[Pointer Events](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_events)、[NippleJS 选项](https://yoannmoi.net/nipplejs/options/)。

### 攻击周围的技能槽位

第一版布局预留右下大攻击按钮和周边小技能槽位；具体槽位数量、尺寸、道具混排及翻页方式仍待细化，不将所有后续技能流程提前算作已实现。

| 技能类型 | 移动交互 |
| --- | --- |
| 自身技能 | 点击请求使用，由共享业务校验可用状态 |
| 指定目标技能 | 对当前有效目标请求使用；没有有效目标时提示选择，不盲目发送 |
| 地面范围技能 | 点击进入选点状态，点地图施放，并提供明确取消按钮；选点不能同时触发普通点地移动 |
| 可选等级技能 | 配置槽位时选择等级，执行时使用已配置等级 |

技能按钮显示实际图标、冷却和可用状态。配置采用“点击槽位 → 选择技能／等级”，支持替换和清空，不依赖拖放。增加按钮只扩展布局和槽位配置，复用已有输入生命周期与施法业务，不重写摇杆和攻击输入逻辑。

## 代码组织与桌面隔离

采用“共享业务与状态 + 两套展示和输入”的结构：

- 移动游戏组件建议放在 `repos/happyro-client/src/UI/Mobile/game/`，独立布局、样式和事件。
- 桌面组件保留原有入口和交互；不在每个桌面事件里散布移动端分支。
- 在游戏 UI 的装配入口统一选择移动或桌面实现；选择方式沿用项目的平台判断，不能仅凭窗口宽度切换桌面模式。
- 角色、物品、技能、快捷栏等数据与业务操作复用。现有桌面组件中耦合的业务逐步提取成共享接口，移动 UI 不另写一套封包逻辑。
- 提取业务时保持桌面调用行为不变；数据更新不能继续依赖隐藏桌面 DOM。每阶段核查封包处理器到 UI 的直接引用并提供清晰的绑定接口。
- 旧移动辅助 UI 在新移动入口启用时退出，避免新旧输入监听器同时运行；桌面原有能力不随之删除。
- 移动端样式限定作用域；UI 点击、滚动不能穿透到地图。游戏场景输入与面板输入明确分界。
- 移动面板展开状态与桌面窗口坐标等 UI 偏好独立保存；共享游戏状态和服务端快捷栏数据，不复制成相互冲突的数据源。
- 进入、换图、退出、断线时统一管理组件生命周期，清理监听器、计时器、触点和输入状态。

## 分阶段范围

1. **入口与首屏骨架**：梳理组件和输入注册点，建立移动游戏 UI 装配入口与独立布局，接入人物信息、状态、小地图、菜单、聊天入口。
2. **移动与战斗操作**：接入左侧摇杆、右侧攻击、目标显示、交谈、拾取、镜头控制和快捷栏显示／使用，完成多点触控和取消状态处理。与阶段 1 共同组成首个可用版本。
3. **背包与装备**：详情、使用、穿脱、数量选择、整理及相关物品操作，全部不依赖拖放或右键。
4. **技能与快捷配置**：技能查看、学习、等级选择、快捷槽位配置，以及不同施法目标的操作流程。
5. **NPC 与交易类面板**：对话、选项、输入、商店买卖、仓库、手推车、摆摊、玩家交易等。
6. **其余系统与完整回归**：任务、队伍、好友、公会、世界地图、导航、设置、退出等；盘点所有实际可达窗口，覆盖启用的扩展系统、职业专属面板和异常流程。

“全部 UI 重构”以完整组件盘点为准，以上是阶段分组，不是对剩余窗口的豁免。尚未适配的入口须记录状态，不能包装成移动端已完成能力。

## 验收要求

- 移动：横屏下无必要操作依赖右键、悬停、双击或拖放；控件不重叠、不出屏，面板可以关闭和返回。
- 输入：支持摇杆与攻击／技能多指操作，释放右侧按钮不结束摇杆输入；地面技能选点不同时触发走路，取消后恢复正常场景输入；点击 UI 不触发场景操作；触摸取消、失焦、换图、退出、旋转后没有卡住的输入状态。
- 业务：道具、装备、技能和快捷栏的数据与服务器一致，操作不重复发送；普通攻击的连击与目标选择策略在实现前明确。
- 桌面：逐批回归相关窗口的右键、拖动、快捷键、焦点、窗口位置保存和原有操作结果。
- 环境：本机浏览器自动检查与 iPhone 实机触控验收分开记录；本机 WebKit 通过不能替代手机验证。
- 构建：完整构建 PWA（`npm --prefix repos/happyro-client run build -- --all`），再用 `./scripts/client/refresh-client.sh verify --no-color` 核对运行入口提供的新产物。
- 进度：分别记录方案、实现、测试、实机确认和提交状态，不以代码存在代替验收通过。


### 阶段 2 本轮落地约定（2026-09-23）

保留点地移动；点怪物先选择，按住右侧攻击才出手，松手取消后续连续攻击，无目标不自动找怪。摇杆拥有移动优先权，移动中攻击不自动追赶；站定攻击复用原接近目标的寻路。松开摇杆停止发送新移动请求，服务端已接受的短路径可能走完。目标为 NPC、物品或传送点时提供上下文按钮；镜头通过菜单按钮调整。三枚技能槽位仍为占位，本轮核心操作完成不等于阶段 2 的快捷使用或阶段 4 的技能配置已经完成。


### 快捷槽位本轮落地约定（2026-09-23）

三个常驻槽位按组翻页，共十二组，映射主快捷栏 36 个服务端槽位；移动端配置与桌面共享。空槽点选配置，已有槽位点按使用，替换／清空从配置入口操作，技能等级在已学范围内选择。右侧普通技能／道具操作不取消左摇杆；地面技能进入独立选点模式时释放移动，重新移动会取消选点。角色已学主动技能及支持快捷使用的背包物品进入候选目录；完整学习面板及特殊技能附加选择窗口另行重构。用户已明确本轮继续实施，手机实机统一在后面验收。


### 背包基础操作本轮落地约定（2026-09-23）

菜单打开独立横屏背包，左侧分类／物品列表、右侧详情／操作；全部、消耗品、装备、其他、已穿戴五类均可点选和滚动。点击物品后使用、穿戴或卸下，每次操作按背包索引重新校验身份与当前状态。服务器回复决定数量和穿戴结果，不在点击时预先改动。非堆叠装备的封包数量缺失或穿脱后为零时仍视为一件，背包与快捷槽共用该规则。

设置快捷槽采用点选目标槽位、查看当前内容、确认替换，映射既有 36 个服务端主快捷槽，不拖放。已穿戴装备可在背包“已穿戴”分类卸下；独立装备部位面板、整理、批量数量选择、丢弃、卡片镶嵌及道具触发的特殊附加窗口后续分批实现。本轮只覆盖普通道具使用和基础穿脱，不将阶段 3 或全部物品相关窗口标记为完成。

面板打开时取消场景触点和移动／攻击并冻结场景；面板自身的物品操作允许执行，但不绕过打开前已有的冻结，也不允许死亡或断线后继续发送请求。关闭恢复原冻结状态，失焦、旋转、换图和断线复用 HUD 的统一清理机制。


### 独立装备面板本轮落地约定（2026-09-23）

菜单启用独立装备入口，横屏按“装备／时装／影子／属性”切换。按服务端实际占用位置展示装备；一件装备占多个部位时显示在所有对应部位，不将可穿戴位置误当成已穿戴位置。点击部位查看说明与卸下；空部位或“更换”列出背包中位置匹配的装备，点击候选查看详情，再点穿戴。左右饰品、左右手等按用户选择的部位发送请求，跨多个部位装备的最终占用和职业、等级等资格仍由服务器判定。

物品数据与业务继续复用移动背包适配层；装备控制器与独立面板分别放在 `UI/Game/GameEquipment.js` 和 `UI/Mobile/game/EquipmentPanel.js`。人物主要属性从封包处理入口同步到按角色实体隔离的共享状态，保留桌面 WinStats 更新，移动端不读取桌面 DOM；穿脱结果与属性分别随服务器回包刷新，不预估属性变化。

本批完成独立部位面板及基础更换，不包含预览试穿、装备方案切换、精炼／附魔、批量整理或技能学习；背包阶段的这些剩余工作继续单独记录。手机实机手感仍按用户安排统一验收。

### 后续前四批落地约定（2026-09-23）

1. 技能面板：职业技能目录与服务器已学技能合并展示；服务器决定可学习资格，确认后每次请求一级；主动技能按已学等级绑定原有 36 个快捷槽。

3. 商店与物品：覆盖普通、点数、限量、普通材料兑换和扩展材料兑换 NPC 商店。点数商店沿用原购买业务使用主点数，材料精炼及其他服务端限制以服务器最终判定为准。点选数量后核对订单再确认，不依赖拖放；背包排序只改变移动列表展示，丢弃需数量及明确确认。
4. 仓库与手推车：仓库由服务端打开，手推车从菜单进入；背包、仓库、手推车按分类选择来源、目标与数量，支持六向转移，已穿戴装备需先卸下。容量、重量及物品数量随服务器更新；移动端完整列表边界清理旧数据，不依赖未挂载桌面窗口的移除事件。

后续仍包括玩家交易／摆摊、任务地图、社交聊天、精炼附魔／卡片／特殊技能附加窗口与其他启用系统，以及统一手机实机验收。具体本轮验证与限制见实施进度。
