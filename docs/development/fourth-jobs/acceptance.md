# 四转验收与范围边界

本页规定基础四转交付的验收范围和抽样方法，不记录通过状态。实际结果记录在对应测试报告和发布说明，不维护旧批次样本副本。常规职业的NPC转职实测见[转职验收](../job-change-review/README.md)，其范围不包含全部20个目标职业或冒险工具独立验收。

## 核心门槛

覆盖全部 20 个目标职业的基础入口和能力。共享机制采用代表样本验证，不要求每个职业、每个技能重复实战；已经执行过的批量结果直接复用。

| 编号 | 功能 | 核心验收内容 | 对应证据类型 |
| --- | --- | --- | --- |
| F01 | 游戏内转职 | 导师可见且可找到；对应前置职业按条件转职，Base 保留、Job 重置；等级不足及未用技能点有拒绝提示 | NPC 实测与目录／脚本核对 |
| F02 | 冒险工具职业目录 | 目标职业可搜索切换，中文名、性别可选项、等级上限一致；拒绝非法性别组合 | 界面测试、角色快照与操作报告 |
| F03 | 等级与组合请求 | 四转能突破 Base 200；支持转职与合法目标等级同请求；拒绝非法组合且不部分变更；回切低上限职业要求明确合法等级 | 工具边界实测、正常经验升级代表 |
| F04 | 特性与 AP 基本操作 | 六特性显示和预算校验正确；特性重置与基础洗点分离；降级／退出特性职业正确结算；AP 获取和消耗代表正常 | 接口／封包测试、特性与 AP 实测 |
| F05 | 主要角色状态保存 | 职业、等级、六特性、预算与剩余点数在重登后保持；已学技能重登后可用 | 保存／全新登录及技能使用报告 |
| F06 | 基础技能可用 | 学习及前置流程正常；自身状态、地面区域和单体攻击各有代表可用 | 分类抽样的学习、施法、消耗与结果报告 |
| F07 | 资料与基础资源 | 职业身体文件可读；目标技能定义、等级、布局及图标接通；补充资源有来源和哈希 | 自动化资料／资源审计、来源清单 |
| F08 | 本机运行入口 | 固定协议及 Renewal；相关服务可用；全量 PWA 构建通过，Gateway 提供对应产物，启动页保留 | 构建、服务状态、产物哈希及实际登录证据 |

完整资源扫描可能包含未引用的旧配置缺口。判断是否阻挡 F07 时，必须记录该缺口的当前引用与影响，不能隐藏扫描失败，也不能把未引用旧条目等同于核心功能不可用。

## 抽样与复测规则

- 按共享处理机制选择样本，记录选择依据、实际结果及覆盖范围；不按职业数量机械增加测试。
- 保留已有快速数据扫描。已通过且相关代码未变的检查不重复执行；有实现变化、失败或实际反馈时才补充针对性验证。
- “抽样通过”只代表所述机制和范围；不得把未测成员写成已逐项实测。
- 特殊机制先记录差异，再按后续路线优先级决定是否验证，不自动增加为基础交付门槛。
- 后续样本先服务当前收益工作包：优先证明玩家操作、服务端结果或角色状态；纯文件存在、映射数量和重复职业样本不能替代更高收益证据。
- 修复已确认的核心缺陷后须复测；代码存在或文件可读不能替代相应行为证据。
- 使用专用测试角色，不改用户已有角色做验收。

每个样本记录运行版本、角色条件、触发方式、预期／实际结果、证据路径及限制。生成报告和截图放在 `artifacts/fourth-jobs/`，临时准备放在 `work/fourth-jobs/`。

## 后置范围与完成判定

特效精修、治疗／召唤等更多专属机制、特殊装备形态、AP 死亡／切图细节以及更多并发边界统一进入[后续路线](acceptance.md#后续范围与处理优先级)，不以旧批次的全项清单作为基础交付门槛。

F01—F08 有对应范围的直接或合理抽样证据，且没有已确认影响核心流程的阻塞，即可交付基础四转。已确认的数据损坏、无法登录、非法核心转职或点数复制问题须优先修复，不能仅通过移入后续路线消除阻塞。

基础功能完成、完整视觉复刻、本机运行、Git 提交及镜像发布分别记录，不能互相替代。

## 后续范围与处理优先级

- 已确认的数据损坏、点数复制、无法登录、转职或等级请求部分生效优先修复，不能移入后续范围来规避核心验收。
- 常用技能文案和玩法反馈按当前源码、服务端结果复核；具体未解决项统一维护在[技能审查待办](../skill-review/pending.md)，不在此复制问题清单。
- 完整官方四转剧情、高等级地图、任务及装备获取渠道需要独立定义需求。
- 治疗、召唤、陷阱／演奏、特殊形态、并发和死亡／切图／重登按实现变化或反馈补充回归；共享机制抽样不代表全部成员逐项通过。
- 全染色、全武器、全方向和逐帧官方复刻不属于基础完成范围；引用资源安装、解析、绘制和玩法结果分别验证。未引用资源缺口统一维护在[资源维护](resources.md#尚未引用的缺口)。

最终发行包按[发布清单](../../operations/release-checklist.md)验收，不以旧主机运行状态、构建号或历史测试数量证明当前通过。
