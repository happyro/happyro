# 四转功能方案与交付

更新日期：2026-09-20。本目录记录基础四转的实际实现、交付证据及后续完善。当前状态以[实现进度](progress.md)为准。

## 目标与结论

基础目标和 R1 常用技能真实战斗闭环已经完成：游戏内可转职，冒险工具可切换四转，可突破 Base 200，可操作特性与 AP，可学习并使用各类代表技能，角色主要状态可保存重登。下一轮处理角色状态生命周期，其次是常用职业形态；视觉精修、内容扩展和无引用资源排在后面。

基础主流程已经实现并在本机运行。验收按共享机制抽样；完整特效、特殊装备动作和少见边界后置，不阻挡当前交付，也不表述为已经全部验证。

## 本轮范围

- 纳入 13 个常规四转职业，以及 7 个扩展进阶职业；按实际机制记录抽样范围。
- 保持 `PACKETVER=20211103`、Renewal，以及客户端和服务端封包设置一致。
- 沿用当前服务端职业经验配置：普通三转按自身上限，四转为 Base 275／Job 60。客户端读取服务端上限。
- 游戏内使用独立中文四转导师；冒险工具保留其管理／调试用途，两者采用各自准入规则和服务端校验。
- 完整官方转职剧情、所有高等级地图与任务内容、全面战斗平衡重做不在本轮默认范围。若追加，应单列工作包。

以上职业和协议范围保持不变。按最新优先级，本轮不再等待全部显示细节完成；已执行事项在进度表，延后事项在后续路线。基础交付不等于镜像发布。

## 维护约定

1. 任务开始、完成、遇到阻塞或调整范围时，更新[实现进度](progress.md)。只有有验收证据的任务才能标记完成。
2. 设计改变时更新实现方案及对应验收项；F01—F08 表示已交付能力，P0—P3 表示风险优先级，R0—R6 表示后续收益顺序。排期只维护后续路线，过程只记入历史。
3. 测试、资源审计和截图等生成物放在根仓库 `work/` 或 `artifacts/`；此目录只保留方案、索引和证据摘要。
4. 本目录是跨仓库协调文档，不替代各产品仓库的代码文档或 changelog。
5. 未经用户明确要求不提交、不推送。后续若提交产品改动，遵循根仓库及产品仓库的 changelog 与提交规则。
6. PWA 重建必须使用 `--all`；若进入镜像发布，先执行[Docker 发布规则](../../operations/docker-release.md)。
