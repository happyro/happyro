# 实现方案

本页描述当前采用的实现和接口规则。交付状态只在[实现进度](progress.md)维护，验收方式见[验收规则](acceptance.md)，未完成事项只在[后续清单](backlog.md)排期。旧方案见[实施历史](history.md)。

## 范围与优先级

本轮交付基础四转主流程：游戏内转职、冒险工具切换、突破 Base 200、特性与 AP 基本操作、基础技能学习／使用以及主要角色状态保存。

支持 13 个常规四转和 7 个扩展进阶职业，固定 PACKETVER=20211103、Renewal。等级上限以服务端职业数据库为准，当前目标四转为 Base 275／Job 60。完整官方转职剧情、高等级玩法内容、所有特效和特殊装备动画不属于本轮完成门槛。

P0／P1／P2 仅表示工作优先级：核心流程或数据问题优先，其次常用功能差异，再处理视觉精修。功能编号 F01—F08 用于关联验收与进度，不表示阶段顺序。

## 跨仓库职责

| 仓库／目录 | 当前实现职责 |
| --- | --- |
| Server | 独立四转导师；职业能力目录、目标等级校验、特性操作及点数结算；复用既有技能、经验和角色保存机制 |
| Client | 职业中文名、搜索与切换界面；服务端上限和特性面板；技能资料、封包与部分特效映射 |
| Admin | 保留冒险工具授权边界，校验并转发新增特性命令；同步职业映射副本 |
| Gateway | 读取运行 GRF 与散文件覆盖；处理客户端 CP949 字节形式的资源路径 |
| 根仓库 | 技能资料生成、资源来源和哈希审计、NPC 导航编排、跨仓库文档 |

职业 ID、性别可选范围、等级上限和特性预算以 Server 为最终权威。Client 展示及提交目标值，Admin 校验授权和请求结构，Server 验证角色规则后变更在线角色对象。成功响应刷新角色快照。

## 游戏内转职（F01）

采用独立脚本 `npc/custom/happyro/fourth_job.txt`，由 `npc/scripts_custom.conf` 加载。导师位于 `prontera,153,193`，中文名称及坐标同步到 NPC 图鉴和导航。

| 路径 | 前置与等级 |
| --- | --- |
| 常规四转 | 对应进阶三转，Base 200／Job 70 |
| 扩展进阶 | 对应前置职业，Base 200／Job 70 |
| 召唤师进阶 | 召唤师，Base 200／Job 60 |

入口拒绝宝宝职业、不适用职业、等级不足和未分配完技能点的角色。确认后调用服务端职业变更机制，保留 Base、Job 从 1 开始；装备与状态适用性由既有职业规则处理，不直接写数据库职业字段，不附送装备或等级。

## 职业与等级操作（F02、F03）

角色快照增加以下能力字段：

| 字段 | 内容 |
| --- | --- |
| `sex` | 角色性别 |
| `jobs[]` | 每项含 `id`、`max_base_level`、`max_job_level`、`traits` |
| `traits` | `enabled`、`values`、`maximums`、`points`、`budget` |

`jobs` 按角色性别和规范职业 ID 筛选，排除不可直接选择的骑乘形态和装扮职业。Client 按组搜索职业，依据目标职业能力显示合法等级。

`character.progression.update` 支持组合提交 `job_id`、`base_level`、`job_level`。先确定目标职业并校验全部参数，再执行变更，避免非法等级请求留下部分转职。高等级四转切回低上限职业时必须同时指定合法目标 Base；不静默截断等级。

降低等级时回收成长点数；基础未分配点不足以回收时重置基础属性。职业等级及职业变化后重新结算技能点，特性按新等级预算协调。正常经验升级继续复用服务端经验表和升级逻辑。

## 特性、AP 与保存（F04、F05）

`values` 与 `maximums` 均使用六项字段：`pow`、`sta`、`wis`、`spl`、`con`、`crt`。

| 命令 | 行为 |
| --- | --- |
| `character.traits.update` | 至少提交一项特性；合并当前未修改项，校验单项上限及六项合计预算，剩余点数为预算减合计 |
| `character.traits.reset` | 仅重置六特性及特性点 |
| `character.stats.reset` | 重置基础属性，保留特性 |
| `character.vitals.restore` | 复用既有恢复操作，包含 AP |

预算由等级成长表加四转奖励点数计算，当前 Base 200 为 7 点。工具降级后若分配超过新预算，清零六项并返还新预算；未超预算则保留。退出支持特性的职业时清零特性和特性点；非特性职业拒绝特性修改／重置命令。

普通特性加点封包的数量使用 16 位编码。AP 获取、技能消耗和最大值复用服务端实现。角色变更通过在线对象及既有保存机制持久化，不新增直接改角色数据库的产品路径。AP 特殊生命周期等未验范围见后续清单。

## 技能与资源接通（F06、F07）

技能资料生成流程用当前服务端定义补齐客户端技能元数据、前置和布局；不修改官方源快照，不从历史翻译归档回写产品。

资源使用 `inputs/runtime/kro-20211105/client/data.grf` 及其 `data/` 散文件覆盖。新增官方技能图标的来源 URL、补丁及提取文件哈希记录在 `inputs/manifests/fourth-job-icons.json`；安装工具校验源与目标文件，原 GRF 保持不变。Gateway 对散文件路径进行必要的 CP949 转换。

普通施法／命中特效与地面单位效果分别映射。已接入的地面效果随单位持续和删除；已明确映射的 BSON 地面动画区分开始、循环和结束，避免重复附着施法者。具体覆盖数量与缺口见[资源差异](resource-gaps.md)，不把资料齐全等同于所有动画完整。

## 运行与维护（F08）

Server、Admin、Client 的接口配套使用；客户端不保留旧快照兼容分支。PWA 构建使用 `npm run build -- --all`，Gateway 提供构建后的 `dist/Web`，首页保留启动页。

实现变更按风险验证：保留快速资料扫描，同类行为按机制抽样；代码未变且已有证据的检查不重复执行。出现影响登录、转职、等级或角色数据的实际问题按 P0 处理；边缘显示与特殊场景按后续清单处理。

提交、推送和镜像发布需用户明确要求，且遵循各仓库 changelog 与发布规则；本机功能可用不代表已经发布版本。
