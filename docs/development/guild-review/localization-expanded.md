# 公会相关名称扩大审查

[返回公会审查](README.md)

日期：2026-10-29。本轮围绕公会相关可见名称、对话标题、菜单与提示开展检查，不将这次文案审查视为又一次完整攻城战斗验收。

## 范围和方法

从 Renewal 的 `npc/re/scripts_main.conf` 及脚本配置入口追踪加载链，共枚举 838 个已启用脚本，筛出 74 个公会相关脚本。除公会、FE／SE／TE 城堡外，补查公会仓库、城堡投资、公会任务、TE 任务与神器制作、公会地下城活动、奥科尼尔和相关引导。某些大任务文件只因包含公会相关入口而入选，不意味着它们的全部剧情功能都经过实机验收。

名称检查使用仓库现有脚本解析器排除注释与函数体中的伪定义，再结合客户端 `NpcNameTranslations.zh-CN.json`、NPC 外观和传送入口规则判断最终可见名称；同时检查动态名称和对话字符串。检查客户端公会／助手／移动社交菜单，并逐条核对实际引用的 65 个消息 ID、相关公会技能名称与服务端提示。后台与冒险工具通过生成目录及导入后的 `catalog_npcs` 核对。

## 发现与处理

| 项目 | 处理 |
| --- | --- |
| 27 个城镇仓库管理员 | 服务端显示名统一为「公会仓库管理员」。原客户端译名表已经能将 `Guild Warehouse Manager` 转为中文，因此此前仅凭脚本英文定义推断界面一定显示英文并不准确；本次统一源名称，减少跨入口差异。 |
| 名称隐藏后缀 | 对前轮及本轮共 144 个改名 NPC 保留 `#` 后缀和 `::` 内部唯一名。城堡管家模板实际读取 `strnpcinfo(2)` 作为城堡标识，不能只保留唯一名。已修复前轮汉化时遗漏后缀的问题。 |
| 公会解散失败 | 消息 401 原为「身份证号码有误，无法解散公会」，改为「公会解散失败」。Gateway 的实际资源响应已验证更新。 |
| 图鉴和导航 | 从源重新生成 API NPC 目录、客户端导航实例索引及图集清单，导入本机 API 数据库；重新完整构建 PWA。 |

仍使用原有内部唯一名是脚本当前数据结构的一部分，不是旧版本兼容分支；事件调用和动态查找继续指向同一 NPC。

## 排除的候选

- `Monster Controler`、`paper_sp_*`、`eff_mvp` 等为隐藏控制／效果节点，不作为普通玩家对话标题批量汉化。
- `Gate01`、`windpath*`、城堡路线标识属于传送入口，移动端通过公共标题函数显示「传送入口」。
- `Event controller`、`Memorial Dungeon Expert`、`Kienna` 等已有客户端中文映射；不能只凭源定义的英文判为缺失汉化。
- 注释块中的英文活动公告、不启用的 iRO 定义不属于当前可见文本。
- 地图 ID、资源路径、格式码、命令、快捷键和 TE／SE 等模式缩写保持原语义；一个韩文命中项是实际音效文件名，未改动。

在上述范围及最终显示规则下，没有发现新的未汉化可见 NPC 标题。此结论不扩展为全游戏、所有未启用脚本或全部剧情分支已完成汉化。

## 验证结果

- 使用当前 map-server 真实加载全部脚本，并运行临时 `OnInit` 校验：144 个 NPC 均可按内部名查到，`strnpcinfo(1)` 中文显示名、`strnpcinfo(2)` 隐藏后缀、`strnpcinfo(3)` 唯一名全部符合预期，失败数为 0。校验脚本位于 `work/`，未加入产品配置。
- 与 Git 基线逐项比较，14 个改名脚本文件的 NPC 唯一名及隐藏后缀保持一致；可见名称符合封包字节长度限制。
- NPC 脚本解析／目录生成相关 13 项测试通过，目录一致性检查通过。
- API 导入后的记录包括 96 个传送旗帜、19 个城堡旗帜、27 个公会仓库管理员、公会投资管理及城堡管家各 1 个。
- `npm run build -- --all` 完整构建通过，Gateway 3338 校验正在提供 `mvt5hzru`。消息资源 401 实际返回「公会解散失败」。
- 地图服务和 Gateway 已恢复。启动仍有本机此前已存在的 `conf/msg_conf/import/map_msg_eng_conf.txt` 缺失诊断，本轮未新增脚本加载错误。
