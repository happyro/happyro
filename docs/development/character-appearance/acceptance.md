## 实施过程记录要求

统一在 [进度与问题记录](progress.md)维护实施状态，避免另建重复的 checkpoint 或临时进度副本。

- 每完成一个阶段、一个职业分支或一轮验收，以及遇到阻塞、修复问题或交接时，及时更新总进度、当前工作、下一步和问题记录。
- 总进度分别列出共用机制阶段、十三个分支实现／桌面验收数量、手机和平板代表性验收数量；按实际完成计数，不用代码完成冒充验收完成，不把旧版骑士／十字军实现计为通用机制验收完成。
- 每个问题记录编号、现象与复现条件、影响范围、根因或待调查项、解决方案、实际改动、验证结果、证据及剩余限制。未验证的方案不得标记为已解决。
- TODO 状态与进度记录同步；实现细节及最终行为归入 implementation.md，测试结果和问题状态归入 progress.md，通过链接关联，避免复制多份结论。
- 验收证据记录对应版本、平台及测试范围；生成产物放在 work/ 或 artifacts/，引用时标明路径。没有提交或没有执行的验证如实标注。

## 并发实施与验收

允许并优先采用并行任务／多代理协作，加快实现与验收；无需为下列范围内的并发再次确认。并发以依赖、文件归属和测试环境隔离为前提，不仅取决于机器性能。原实施机器为 10 个逻辑 CPU、16 GiB 内存，以下仅为该配置的起始安排，执行时按内存压力、交换增长与交互响应调整。

### 工作拆分与依赖

| 阶段 | 可以并行 | 必须先完成的依赖／串行边界 |
| --- | --- | --- |
| 资源与规则核对 | 按职业分组并行核对 ID、性别、资源和特殊形态；并行准备验收用例 | 一名集成人员汇总权威配置、标识和接口契约，统一缺失形态规则后再开展依赖这些定义的实现 |
| 共用机制实现 | 契约确定后，服务端、客户端、Admin 分工实现；测试用例可同步编写 | 共用协议与配置变更由负责人协调，不能各自决定字段或编号；跨端联调在配套实现集成后进行 |
| 分支接入 | 普通职业与特殊形态资源核对、独立配置和测试可分组推进 | 共用解析器、映射汇总文件由指定负责人维护，避免多人同时写同一文件 |
| 自动化验证 | 客户端测试、服务端白名单测试、Admin 测试可独立运行；条件允许时与另一仓库构建并行 | 使用独立输出目录；数据库测试不得重置或污染实机验收数据库 |
| 实机验收 | 稳定版本上，桌面按职业分组验收；手机、平板代表性回归可同时开展；下一批实现可在隔离工作区继续 | 先通过构建、基础联调与冒烟检查，再配套部署验收版本；同一角色、浏览器会话或共享地图操作不能被多个任务同时控制 |

### 本机并发起点

- 实现／调查默认安排最多 4 个并行工作流（含集成负责人），受当前可用代理槽位限制；优先按仓库或互不重叠文件分工。
- 服务端编译先使用 6 个编译任务；最多同时运行一个服务端构建和一个完整 PWA 构建。测试 worker 使用显式上限，避免每个任务都占满全部 CPU。
- 浏览器实机验收先运行 3 组独立会话，可分别承担桌面、手机和平板布局回归；每组按需要分配本人／旁观者两个账号。资源稳定且隔离充分时可增加到 4 组，不默认同时启动十三条职业线。
- 编译、PWA 构建和多组浏览器争抢资源时，优先降低构建／测试并发以保持验收稳定；测量性能表现时暂停竞争负载，避免把本机资源争用误判为产品问题。
- 浏览器自动化若只能共享一个可控制页面，则该工具上的页面操作串行；只有独立上下文、会话或设备才并行。模拟手机／平板视口不能替代尚未执行的真机验证。

### 隔离、集成与结果归并

- 为每个任务分配仓库／文件归属、账号与角色、浏览器上下文及证据输出目录；需要修改同一文件或构建不同版本时使用独立工作树／输出目录并由负责人集成。
- 每批验收固定提交或源码快照、构建标识和配套服务版本；同一运行环境验收期间不覆盖 PWA、不重启服务、不重置数据库。版本切换由集成人员统一安排，切换后重新冒烟并按改动影响确定回归范围。
- 同时推进下一批实现与上一批验收时，将开发构建与已部署验收产物隔离；若必须同时验收不同版本，使用独立服务端口与测试数据库。
- 所有并行任务回报实际版本、范围、问题编号和证据；由一名负责人归并 progress.md 与 TODO 状态，避免覆盖记录、重复计数或混用版本结果。
- 记录实际并发数、资源瓶颈和降并发原因；只有相关验证通过才标记对应阶段完成，不以并行任务结束代替验收通过。

## 三端验收分工

三端均需验收，但不重复执行三套完整职业矩阵。以下是每次扩展的验收标准；本轮完成状态仅以 [进度与问题](progress.md) 为准。

| 平台 | 验收范围 |
| --- | --- |
| 桌面端 | 完整功能矩阵：十三个分支及实际开放选项，适用性别、步行／骑乘／机甲、选择与恢复默认、缺少对应形态时的显示与恢复、本人及旁观者同步、切图重登、武器附件与动作；覆盖下方功能验收要求 |
| 手机端 | 代表性回归：普通职业、服装与坐骑绑定职业、缺少对应形态时显示真实职业形态并在解除后恢复选择三类；检查触控选择、提示、布局、选角与装备预览、横竖屏 |
| 平板端 | 独立执行与手机相同的三类代表性回归，核对平板布局、触控、提示、预览及横竖屏；不能直接沿用手机验收结果 |

- 桌面端完成完整功能矩阵；手机、平板分别完成三类代表性回归，不以桌面通过替代另外两端。
- 任一端发现独有渲染或交互问题时，按影响范围扩大该端职业、状态及资源组合的测试，修复后回归。
- 验收证据分别记录平台、设备／浏览器、实际版本、代表职业及结果；模拟视口与真实设备验证须如实区分，未测项明确保留。

## 验收要求

- 验证风鹰选择猎人、机甲大师选择铁匠：进入特殊形态显示真实职业的完整形态，解除后恢复所选外观；骑乘期间切换选择、切图和重登后仍保持此规则，本人、旁观者及适用预览一致，保存值与下拉框选择不被重置，提示正确。
- 无坐骑的普通职业仅改变人物职业外观；外观切换不新增、移除或改变已有随行单位，不改变实际骑乘状态、真实职业与战斗规则。
- 有坐骑分支只能选择完整职业外观组合；步行／骑乘切换沿用同一选择，不提供独立坐骑外观设置，界面与接口均不能组合不匹配的服装和坐骑。
- 选择、恢复默认、非法跨分支／阶段请求，以及适用性别和资源组合分别检查。
- 真实职业、技能树、装备资格、属性、费用和实际骑乘／随行状态保持不变。
- 本人和旁观者实时同步；进出视野、切图、正常重登、死亡复活及默认路径回归。
- 对实际开放的外观检查移动、待机、攻击、受击、施法、武器附件和技能效果位置；步行与特殊形态分别记录。
- 三端选择入口、选角及装备预览检查；资源失败、超时、快速切换与迟到回调按现有规则回归。
- 证据记录实际版本、开放外观清单和未测组合；角色名称或身体资源加载成功不等于整线验收通过。

当前验证细节与已知限制见[实现记录](implementation.md)。新的实测结果与待办应随实际工作更新，原转职及技能审计的完成状态不迁移到本功能。
