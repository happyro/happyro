## 规则与配置

高阶职业可选择同分支较早阶段的完整职业外观。普通职业只换人物身体；有坐骑分支的人物服装和对应坐骑绑定到同一个选项。真实职业、技能、装备资格、属性、费用、实际骑乘和随行单位不由外观命令修改。详细产品边界见 [产品规则](rules.md#普通职业与坐骑职业的显示规则)。

唯一维护源为 [config/character-appearance.json](../../../config/character-appearance.json)。定义分支、适用性别、实际职业及阶段、稳定选项 ID、显示职业、绑定骑乘职业与标签；明确的 mountedOf 引用表示真实战斗骑乘职业，不从名称或编号大小猜测。当前 13 分支、81 职业条目、39 非默认选项：

0 为默认。阶段 1 二转、2 进阶二转、3 三转（含进阶变体）、4 四转；只允许 option.stage < actual.stage。一转、初心者、婴儿、第二服装和染色组合不在候选白名单。第二服装仍遵循既有显示优先级。

[生成工具](../../../tools/character-appearance/README.md)同步 C++ 白名单、客户端资源解析表、Admin ID 白名单，三个产物都记录 canonical JSON SHA-256。check 模式逐字节核验，不只比较摘要；生成前验证唯一 ID、阶段、性别、引用、uint16 容量及身体／骑乘配对。新增普通分支维护配置后生成三仓并完成验收；新的特殊形态可能仍需代码。

## 服务端与 Admin

[game_control_appearance.cpp](../../../repos/happyro-server/src/map/game_control_appearance.cpp)独立负责快照、读取、校验、修改和保存值重校验；骑乘模块不再承担外观职责。

快照独立字段：

```text
characterAppearance: {
  current: number,
  options: [{ id, name, mountLabel, fallbackOnMount }],
  reason: string
}
```

选项由真实职业、阶段和性别决定，不要求骑乘技能或当前骑乘。名称来自配置；空骑乘标签为空字符串。无较早阶段选项时只有默认，界面隐藏多余选择框。

命令保持 character.appearance.update，payload 只接受 appearance 整数。Admin 使用生成的已知 ID 列表，服务端最终拒绝未知 ID、跨分支、同阶段／越阶段和不适用性别。无效参数返回 400；资格不符为 appearance_job_required（409）；死亡、NPC 对话、交易、仓库、摆摊或采购期间为 appearance_busy（409）。角色归属、授权、限流及幂等沿用维护接口。界面禁用忙碌控件，请求失败后重新获取当前资格与选择。

保存仍为角色变量 HappyRO_CharacterAppearance，不新增数据库字段或迁移 SQL，不读取旧键或旧命令。更新写变量、发送附近外观通知、保存角色，不调用转职、骑乘或召唤。转职、直接修改性别、角色／账户改性别，以及登录角色变量就绪后统一清理不适用保存值；缺少某个骑乘身体不属于资格失效，不能清空选择。

## 协议

PACKETVER 固定 20211103。两种通知均 8 字节：uint16 封包 ID、uint32 角色标识、uint16 外观选项，容量覆盖当前及后续配置。

| 通知 | 编号 | 标识与用途 |
| --- | --- | --- |
| ZC_HAPPYRO_CHARACTER_APPEARANCE | 0x0d08 | 地图 actor ID；实时选择及进入视野同步 |
| HC_HAPPYRO_CHARACTER_APPEARANCE | 0x0d09 | 角色 ID；角色列表后发送保存选择 |

角色服务按账号批量读取变量，并用实际职业与性别复用资格校验；SQL 失败时正常提供默认选角。客户端按角色 ID 缓存外观，重复列表保留缓存，换登录会话清理。三端必须配套更新；未提供旧客户端协议兼容。

## 渲染与特殊形态

[CharacterAppearance.js](../../../repos/happyro-client/src/Renderer/Entity/CharacterAppearance.js)使用生成配置解析，EntityView 保留真实 _job，独立 renderJob 只用于身体、武器、盾牌、披肩等资源；攻击动作通过外观基础职业解析。任务、技能树、装备资格仍读取真实职业，不使用外观职业。

优先级为既有变身／特殊服装／商城骑乘 > 所选职业外观 > 真实职业默认。所选外观使用原始身体配色，不修改已保存染色；恢复默认后沿用原染色。

步行使用 option.job；实际战斗骑乘时使用完整 option.mountedJob。若该值为 0，则让位于真实职业的完整特殊形态：风鹰选猎人骑狼时显示风鹰骑狼，机甲大师选铁匠驾驶时显示真实机甲；解除状态恢复所选步行身体。保存值和下拉选择不变。界面不再显示缺少骑乘形态的独立提示，保留外观选择与骑乘名称。

手推车、狼／猎鹰随行、生命体和元素精灵是独立状态，不因外观选择增删或换身份。

### 资源失败与竞态

未选择外观时沿用原有默认加载流程。外观主体必须 SPR 和 ACT 都成功才切换；任一失败或 8 秒超时，在本地暂停该实体外观，恢复真实职业形态，保留服务端选择，不循环重试。重新选择默认后再选目标可重试。

切换、下骑、更新身体和移除实体取消旧等待；代次及视图序号拒绝过期主体和附件回调。附件资源兜底保留真实装备编号。此逻辑只处理职业外观资源失败，不掩盖默认资源故障或断线。

## 入口与预览

桌面、手机、平板共用冒险工具「角色」中的独立职业外观组件。面板显示服务端允许的名称、当前选择、绑定坐骑标签和缺形态提示，无独立坐骑皮肤设置。

- 选角共享组件使用生成白名单，支持所有 39 项及适用性别，真实职业文字不变。
- 装备、换装、试穿和他人装备共用预览实体，传递外观、身体、性别、effectState 与 allRidingState；缓存签名包含这些状态，替换实体时清理旧加载。
- 设置预览状态时先 allRidingState 后 effectState，避免商城骑乘状态的 setter 清掉普通战斗骑乘；资源失败实体的预览显示默认但不修改选择。
- 旧版装备窗口直接绘制本人实体。公会头像只显示头部，新建角色不属于已有保存外观入口。

已知协议边界：他人装备预览从当前可见实体取得外观与状态；目标离开视野后，原装备封包不包含这些字段，仍显示真实职业预览。本轮未扩展该协议，不宣称视野外他人预览支持职业外观。

## 资源和验证边界

当前核对覆盖 120 对身体 SPR／ACT（240 文件），男女及已有特殊形态通过真实客户端解析，ACT 均有 104 个非空动作入口，SPR 帧尺寸非零，记录路径、哈希及真实职业枚举对应。证据在 work/character-appearance/resource-audit/。

身体解析不证明八方向动作、武器附件或技能效果位置正确。首版仅骑士／十字军的历史验收不迁移到本轮；当前部署版本、自动化测试范围、实际游戏证据、未测组合与真实移动设备缺口统一见 [progress.md](progress.md)。

### 验收中发现的死亡实体生命周期修复

死亡玩家的尸体需要继续响应复活、离开视野与外观通知。客户端对玩家死亡保留实体索引，直到真正离开视野等事件清理；怪物死亡及普通淡出的索引释放保持原行为。修复防止复活回图后旁观者残留旧尸体。生命周期自动化、隔离新构建及共享入口mvdtxw0d的正常死亡复活／原地恢复实测均已通过，部署状态及证据见 [CA-008进度](progress.md)。
