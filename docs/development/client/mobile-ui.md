# 移动端 UI 开发与验收

布局与组件接入规则以客户端的[菜单布局](../../../repos/happyro-client/docs/ui/mobile-menu-layout.md)为准；登录与恢复见[连接恢复](../../../repos/happyro-client/docs/network/connection-recovery.md)。根仓库只维护跨端验收边界，不复制组件尺寸、设备断点或已完成批次。

## 开发约束

- 手机横竖屏、平板、分屏均按实际可用空间布局；密度、方向和内容宽度分别判断，沿用共享布局组件。
- 触控流程不依赖右键、悬停或拖放；面板阻止误触地面，旋转保留业务草稿，关闭释放监听和迟到回包。
- 金额、物品身份、目标、权限和最终结果以服务端为准；等待期间防重复提交，不重放断线前的交易或技能操作。
- 桌面鼠标、键盘与焦点行为必须回归；模拟视口、组件测试、实服交互和真机分别记录，不能互相替代。

## 待核验范围

以下是尚需确认的覆盖边界，不代表全部存在缺陷，也不沿用旧批次的开发顺序。

- 移动端自动拾取列表截断、翻页跳顶和真实滑动手感的用户反馈。
- iOS/Android 后台冻结、锁屏、系统回收页面与恢复行为；屏幕常亮受浏览器和系统策略影响。
- 真机软键盘、横竖屏切换、平板分屏、多指移动与技能操作、浮层和长内容。
- 双方交易、摆摊、商店、邮件附件、银行、仓库容量/重量、宠物进化等真实消耗场景。
- 伴侣指定攻击/移动、技能详情与状态同步；低频商城/奖励、验证码、装备比较及聊天室窗口按实际可达性复查。
- 冒险工具自动寻路仅支持当前地图；跨地图路线预览不等于自动完成跨图交互，需分别验收寻路、停止和传送。自动战斗不支持全地图巡逻。

当前发行包统一使用[发布验收清单](../../operations/release-checklist.md)，只把实际执行过的范围标为通过。复现、截图和日志放在 work/ 或 artifacts/，产品行为变化写入对应仓库 changelog。


## 菜单样式维护

组件尺寸、设备断点、`data-menu-arrangement`、底栏角色和样式加载顺序统一由客户端的[菜单布局规范](../../../repos/happyro-client/docs/ui/mobile-menu-layout.md)维护。新增菜单沿用公共布局与按钮规则，更改布局时清理被替代的覆盖样式；根仓库不复制具体尺寸和逐菜单实现。

## 冒险工具交互验收


在手机游戏菜单打开「冒险工具」，或点击右上角小地图直接进入地图页。顶部标签按账号权限展示地图、魔物、NPC、物品、角色属性和游戏设置；布局按实际内容宽度调整，不以设备名称或横竖屏单独决定分栏；空间充足时保留左右布局，窄屏使用对应的紧凑布局与列表／详情切换。返回列表保留查询与滚动位置，具体布局规则以本页链接的客户端规范为准。

验收需覆盖手机横竖屏、平板竖屏及分屏：真实小地图与蓝色方向箭头、地图选点、NPC 标记、寻路及传送（包括计算中防重复启动、停止后即时停步、切换 NPC 后启动新路线）；魔物筛选、属性、掉落、分布及召唤；NPC 查询和位置；物品筛选、分页、发放数量及 Zeny 输入；角色等级、点数、职业、恢复、基础与四转素质、技能操作；经验、15 项掉落倍率、导航和召唤规则。高影响操作保留确认，权限不足时隐藏分类或禁用操作，并展示服务端错误。

确认底部按钮完整可触摸、详情与长表单可以滚动，键盘弹出时保持内容布局稳定并按浏览器可视区域裁切；关闭、切图及断线后应释放输入锁与订阅，迟到的请求不得重新打开窗口。桌面冒险工具仍使用原窗口，两端共用功能注册与操作服务。自动化验收可拦截修改请求核对参数与错误反馈，避免更改实际角色及全服设置。

## 聊天频道与私聊对象

移动端聊天分类同时决定发送目标，不再提供底部发送频道下拉框：附近、队伍、公会、氏族发送到对应频道，未加入对应组织时禁用发送；全部消息、系统、战斗仅供查看，保留置灰的底栏，不能默认回退到附近。

私聊对象列表常驻：横屏位于分类右侧、消息左侧，竖屏位于右侧消息区域下方。每个对象选项使用灰蓝色细边框，选中项使用金色边框，列表不加外框；长名称显示省略号和未读数，竖屏最多显示四行对象，横屏按可用高度伸展，超出各自高度后滚动；竖屏分类分隔线贯穿列表底部。点击后在消息顶部以黄色完整显示对象名；正文采用左对齐的“我：正文／喵：正文”（自己／对方），不使用气泡或重复角色全名。“新私聊”固定在对象列表上方；横竖屏均直接打开公共移动端输入编辑器，标题为“新私聊”，占位为“输入角色名”，点击“开始私聊”添加并选中，不再经过中间确认弹窗。取消不添加，重复名称直接选中已有对象，不在添加时查询存在性或在线状态，实际发送时由服务端反馈。角色名按协议限制为最多 23 个 UTF-8 字节（纯中文最多 7 字），新建和发送共用校验，错误直接显示在输入弹窗或聊天记录中。上一条私聊尚未收到回执时阻止再次发送，保留草稿，避免覆盖回执对象；切换对象不会改变已发消息的回执归属，退出登录清理待处理状态。其他人的新私聊不改变发送对象。全部消息的私聊来信显示“[私聊] [角色名]: 正文”，发送记录显示“[私聊] 回复 [角色名]: 正文”；仅来信保留蓝色下划线“回复”链接，点击进入对象会话，不立即发送。附近、队伍、公会、氏族中，其他玩家的消息使用“发言”链接，点击只切换对应发送频道；自己的发言、频道通知和服务端欢迎消息不显示操作入口。队伍按封包账号 ID、氏族按封包角色名识别自己，公会封包仅提供带角色名的文本，使用完整名称前缀匹配。

每个对象右侧提供“×”删除按钮，仅移除列表对象，保留聊天记录和草稿；删除当前对象后清空发送目标并禁用输入，不自动切换到其他对象。历史消息不会使删除的对象重新出现，新来信、主动新建或点击历史消息回复可以重新显示。私聊失败仅显示在聊天记录中，不额外弹出 toast。

草稿按频道和私聊对象分别保留；发送后聊天面板保持打开，表情发送不清空文字草稿。对象、草稿和已读状态只在当前 HUD 生命周期内保存，不是跨登录聊天历史。收到／发出私聊及失败回执均携带明确对象元数据，不从展示文案猜测对象。

2026-10-19 体验版已完成组件／HUD／输入编辑器相关 95 项测试、完整 PWA 构建，以及手机／平板模拟视口的私聊往返、附近消息、只读分类、未加入组织和横竖屏布局检查；另在本机开发服务 `3338` 使用 JobAuditM／JobAuditF 复验私聊往返与只读禁发，直接使用 Gateway 提供的新构建。证据位于本机 `work/chat-ui-review/`；未作为 iOS／Android 真机验收或所有聊天类型的完整服务端审查结论。


## 场景玩家操作

移动端选中其他玩家后，操作区单行依次显示“私聊、装备、好友、交易”，不显示该区域的手动操作／自动战斗状态文案。私聊进入所选角色会话，查看装备遵循服务端公开权限，复用移动端装备菜单的只读模式，提供装备／时装／影子分类与图片说明，不提供卸下、更换或本人的属性数据；对方未公开装备时显示明确提示。好友申请成功发送后 toast 提示“已发好友请求”，已是好友时保持“好友”文案并禁用。交易使用统一移动端确认弹窗，确认时重新校验目标并遵守服务端限制。摊位仍保留“查看摊位”入口；自己、NPC 和魔物不展示这组玩家按钮。点击前重新校验当前目标，防止目标离开或切换后误操作。

快捷键说明区与技能菜单共用 `.inventory-item-description` 滚动容器，外层只负责布局并隐藏溢出，不形成第二层滚动；顶部固定为“当前位置 X：技能名 · Lv.X”单行，物品显示“当前位置 X：物品名”，空位置显示“当前位置 X：空位置”；长名称省略。实际说明滚动元素设置 overscroll-behavior-y: none，避免边缘回弹；定时刷新不重建未变化的标题文字。技能和物品说明遵循同一规则，手机／平板横竖屏均适用。


## 社交成员与请求弹窗

右下工具栏固定为「动作／取消」「战斗设置」「自动战斗／停止战斗」；自身与随行动作单独成行、无外层边框和背景，展开动作时隐藏战斗提示，取消后恢复。左侧负责展开自身动作及取消玩家／随行单位选择，右侧保持战斗开关；考场中右侧仍是受目标资格限制的「攻击」。展开自身动作停止自动战斗后选中自己；取消时清除场景输入和焦点。分页栏保持独立。

好友、队伍、公会列表统一一行一项，管理入口和成员共用选中高亮，定时刷新保留选择，成员离开后回到管理入口。队伍和公会列表保留自己，这是完整成员名单的一部分；选中自己只查看成员资料，标注“自己”，不允许私聊自己、转交队长给自己或移除自己。会长不能在自己的成员详情修改自身职位；离队、退会仍从管理入口执行。

公共 MessageDialog 复用当前 Confirmation 样式与移动端遮罩。2026-10-19 审查覆盖好友请求、队伍邀请、公会邀请、同盟申请、收到交易请求及公会提示：这些入口均经过 UIManager 的移动端分支，统一更新；宠物／生命体／佣兵使用同一公共确认入口，也同步更新。NPC 商店买卖选择虽保留桌面 WinPopup 实现，但移动端封包分支使用 mobileNPC.deal，不会进入该桌面窗口。桌面端继续使用原有窗口。本次不代表所有低频窗口均完成真机验收。

成员详情刷新仅比较展示字段，不序列化包含角色引用的完整成员对象，避免同屏队员的生命数据产生循环引用错误。

空列表提示应占列表完整宽度，不得落入双列物品网格的单个格子。手推车／仓库、背包空分类及任务空列表统一跨列，手机和平板均适用；空间不足时自然换行，不强制 nowrap 或隐藏提示。邮件物品空列表已有跨列规则，社交与商店采用单列列表。

社交成员详情统一采用名称标题、在线／离线状态标签和标签—内容资料行。好友显示姓名、在线状态、等级和地图；打开社交时每 5 秒通过 HappyRO 好友资料封包查询在线好友，不依赖同屏或同队。服务端只返回请求者好友名单内的在线角色资料，并限制请求频率；离线好友不展示旧地图。好友和队伍地图统一按地图名称表显示中文，无法识别时显示未知地图。队伍展示队伍名、所选成员身份、等级与地图，公会展示公会名、职位和等级；好友、队伍、公会空列表不显示“暂无成员”，创建公会不显示材料检查提示。缺少的数据显示未知，不推断未提供的状态。长名称自然换行，成员操作沿用原权限规则。

菜单“新邮件”表示仍有未读邮件。完整收件箱回包、成功读取和删除结果同步更新该标记；打开邮件列表本身不代表全部已读，读取失败也不清除提示。

摆摊主界面为可选商品与摊位清单两栏，中间箭头通过统一数量弹窗添加或移回商品，加入时设置单价；核对开店弹窗中输入摊位名称，收购同时输入预算，名称提示仅放在输入框中。清单带物品图标。营业后显示商品与成交记录；自己的摊位牌子也可见，点击自己的牌子或再次使用摆摊／收购技能打开管理，关店后牌子同步消失。

移动端交易主界面在平板及手机横屏为可交易物品、我方、对方三列；手机竖屏按对方、我方、可交易物品三行排列。数量及物品说明通过统一弹窗展示，报价列表保持图标与名称的横向布局。锁定及成交仍须服务端确认；桌面按钮明确区分锁定中、报价已锁定、等待双方锁定与已确认等待对方，禁止重复提交。
