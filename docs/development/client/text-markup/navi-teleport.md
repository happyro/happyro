# NAVI 提前审查与传送实现

## 当前行为

NPC 对话中的 NAVI 使用结束对话后的独立入口；任务、物品中的 NAVI 直接打开现有冒险工具地图或魔物图鉴。桌面和移动端共享发布清单。

### NPC 对话

- INFO 在发布清单中属于可传送坐标时，文案即可点击；不再要求目标 NPC 存在、名称一致、入口匹配或预审连通落点。禁传地图和非坐标目标保持普通文字。
- 点击只保存最新导航目标，复用冒险工具的标准 toast：“已加入导航，结束对话后可传送。”，按现有 toast 时长自动消失；不发送任何 NPC 回答、关闭或中止封包。
- 正常结束对话后，在移动端右下角显示“打开地图 / 取消”独立按钮行，复用“动作”样式并在显示按钮时隐藏战斗信息，桌面在右下角战斗辅助区域提供相同入口；对话再次开始时入口暂时隐藏。打开或取消后清除目标，断线也清除，异步加载期间取消不会迟到打开。
- 打开地图标记原坐标，地图 UI、关闭、寻路、传送均沿用普通冒险工具，不增加专用模式或行为。服务端传送保护保持原样。

### 物品、任务等其他入口

- 任务说明／追踪、物品说明／装备比较中的已批准坐标链接：直接打开普通冒险工具地图并标点，不自动传送、不增加网络预检。
- 魔物目标：清单有有效魔物结果时可点击，打开对应魔物图鉴及分布。
- 未审查、禁传或无有效目标的链接：保留普通可读文字，不提供点击样式或键盘入口。
- 原窗口暂时隐藏，保留 DOM、选中项与滚动位置；只查看地图／图鉴并关闭时恢复原窗口。开始寻路或成功发出传送请求后释放原窗口，之后关闭地图不再弹回。请求在本地被拒绝时仍可关闭返回；服务器拒绝、超时按原规则提示，不自动重试。
- NPC 对话仍在进行时，服务端与冒险工具的对话保护保持有效；非 NPC 文本链接不会发送回答或关闭封包。
- 切换目标、原窗口被替换、断线或异步加载迟到时，不恢复过期窗口。加载失败恢复原窗口并提示失败。
- 地图 UI、导航／传送条件、关闭行为均复用普通冒险工具。坐标传送成功静默，实际到达确认及异常提示保留。

桌面与移动端使用共享安全富文本渲染；彩色 NAVI 的显示文字与 INFO 属性分开处理，物品／任务中的 HTML 保持转义。

## 清单及统计口径

生成器：`tools/resources/navigation/review.py`。发布清单：`repos/happyro-client/src/DB/Navigation/NaviTargets.json`。

当前产物为 **2410 个规范化 INFO 目标**：2048 个坐标动作、40 个魔物动作、322 个禁止直接传送。来自 7377 条展开引用；NPC 源码中的 593 处包含 12 处依斯鲁得动态地图调用，按实际 5 个地图实例展开为 641 条引用，因此比审查报告的 7329 条原始出现次数多 48 条。不是新增了 48 处对话。

清单包含 `schema`、`accessPolicy`、`version`、`sources` 和 `entries`。INFO 的地图名与数字字段规范化，但保留模式参数；相同地图坐标、不同模式的未知链接不会因为坐标相同而自动放行。每个目标记录批准的坐标、真实魔物 ID，或阻止原因。没有条目时默认拒绝。

`accessPolicy` 固定为 `adventure-tools-server-rules`：沿用冒险工具现有坐标传送开放范围，不声称执行入口 NPC 的等级、任务进度或收费条件。若某个地区必须遵守额外任务门槛，应在服务端建立目标访问规则，并重新审查；客户端清单不是权限安全边界。

审查使用已提交的 Renewal 数据及 `db/import-tmpl` 发布基线。本机 `db/import` 同名文件若存在且与基线不同，生成／核对会明确失败，避免本机私有覆盖悄悄变成发布依据。

静态落点审查还排除已加载 NPC 声明的触发格及两格安全边距，覆盖脚本、传送点和复制实例。`rachel,176,80` 位于大范围任务触发区，12 格内没有安全候选，因此提前说明“目标附近没有已确认的安全落点”，不再先发出注定被拒绝的传送。运行时新增触发区、角色占用等仍由服务端兜底。

## 提前审查和构建门禁

1. 修改 NAVI、地图支持、地图缓存、加载脚本、魔物资料或传送实现后执行：

   ```sh
   python3 tools/resources/navigation/review.py generate --no-color
   ```

2. 审查 `work/navi-review/navi-targets.json` 与 `navi-targets-evidence.json` 的变化。核实批准／阻止状态及来源，不能仅为了构建通过而覆盖旧清单。
3. 完成审查后将产物更新至客户端 `src/DB/Navigation/NaviTargets.json`，再执行：

   ```sh
   python3 tools/resources/navigation/review.py check --no-color
   ```

4. 客户端使用 `npm run build -- --all`，保持 PWA 启动页及全部查看器。构建入口先校验发布清单摘要和客户端来源；清单 JSON、支持地图表使用固定 LF，避免检出换行差异造成摘要误报。

门禁分工：

- 根仓库 `check` 重新生成完整决策并比较，检查输入哈希和新增／删除源文件，不仅检查 JSON 的自有摘要。
- `scripts/client/refresh-client.sh build`、`tools/release/release.py stage build` 在实际构建前执行完整检查，失败时不继续构建。
- Gateway Dockerfile 增加独立审查 stage，复制服务端、翻译源与清单进行完整核对；客户端 builder 必须消费此 stage 的清单，不能绕过它直接构建。
- 独立客户端 checkout 的 `scripts/verify-navi-review.mjs` 核对清单完整性、策略与客户端拥有的源文件。它不声称能读取 checkout 外的服务端资料；发布构建由前述根门禁／Docker stage 完成跨仓库核对。
- 构建过程不会自动生成并发布新白名单。

## 服务端兜底与对话安全

`happyro_map_teleport` 保留权限、跨图、地图限制、职业进图、边界、冷却以及周围 12 格安全落点搜索。提前找到静态候选格不保证执行时没人占用，也不替代服务器的 OnTouch／NPC 邻近排除。

新增结果 `8 / HAPPYRO_MAP_TELEPORT_DIALOGUE_ACTIVE`：`npc_id`、脚本状态 `st` 或 NPC 进度条仍活跃时拒绝实际传送，保留对话、位置、冷却及脚本状态。只读落点预览不受此新增条件影响。没有使用会残留的 `npc_shopid` 作为永久阻塞条件。

结果 `9 / HAPPYRO_MAP_TELEPORT_NO_SAFE_CELL` 表示坐标合法但附近没有安全落点；结果 `6` 只用于非法／越界坐标。地图结果 `10 / HAPPYRO_MAP_TELEPORT_MAP_NOT_READY` 与 NPC 结果 `9 / HAPPYRO_NPC_TELEPORT_MAP_NOT_READY` 拒绝尚未生成、未完成加载或离线的角色，避免 `pc_setpos` 只排队 `rewarp` 却被误认为已经到达。加载期封包分发只额外允许这两种导航请求进入明确拒绝逻辑，不开放其他游戏操作。

客户端收到成功回执后仍保持操作等待，只有真实地图、角色坐标匹配且加载完成、角色存活，才确认完成；坐标传送不弹成功 toast。地图完成事件立即核对，定时观察作为补充；回执等待 8 秒、实际到达等待最多 30 秒，超时明确提示结果尚未确认并释放等待状态。断线与发送失败同样清理状态，任何路径均不自动重发传送；加载中或已有坐标／NPC 传送时禁止重入。导航工具按钮与 NAVI 文本使用同一个操作服务。

不能用 `CZ_CLOSE_DIALOG` 自动取消任意对话：`npc_scriptcont` 中 STOP 状态会恢复 RUN，而 next 与 close2 都可能处于 STOP；自动发送可能执行后续任务／奖励。即使 UI 显示“结束”，也不能凭它判断脚本必定安全终止。NPC NAVI 等待玩家正常结束对话，所有入口仍使用活动对话保护。HTTP 控制接口同步映射为 `navigation_dialogue_active`，API 返回明确中文原因。
