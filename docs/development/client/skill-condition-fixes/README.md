# 战斗设置技能条件修复

本目录记录 2026-10-26 真实客户端测试后的统一修复。历史基线见[实机测试记录](../skill-conditions/live-testing.md)，该记录保留旧运行版本的结果，不用新修复覆盖原始证据。

## 提示规则

只有已知、足以确定不满足的条件才显示原因并影响自动技能选择。缺失字段、未同步的状态、无法确认的材料豁免或最终费用都不是“不满足”；无法判断时不提示、不置灰、不据此阻止使用，施放结果由服务端裁决。无提示不表示任何地图、目标或状态下都保证成功。

- 宝石、机甲燃料存在服务端免耗例外，客户端无法准确确定时不显示缺料。
- 水域及动态场地未完整同步，不凭静态地图猜测可施放性。
- 技能列表的 SP 费用是基础值，不能覆盖装备折扣、精灵增耗等最终计算，不以此直接提示“SP 不足”。
- 阿修罗的连段球数未完整同步时，只使用可确定的最低要求，不按普通施法的五球要求误报。
- 真实数值 0 与字段缺失不同；可确认的缺武器、盾牌、材料、冷却等仍正常提示。

## 修复清单

### 动态技能列表

桌面和手机／平板共用面板按技能编号增删、更新和排序。获得或失去临时技能时，不再需要关闭重开；保留已有卡片、选择、滚动位置和焦点。当前焦点技能被移除时转到普通攻击。自动刷新不隐式保存或改写配置。

### 目标标记

利用现有状态封包同步仆从标记及信仰烙印，仆从标记附带真实归属。目标进入视野时同步当前状态；客户端区分已知开启、已知关闭和未知。只对明确不符合的目标提示或跳过，未知归属不猜测；存在合法或未知目标时，不在全局面板禁止该技能。

### 未知条件

清除把基础 SP、缺失数值、未知武器类型或未同步连段当成明确失败的判断。保留服务端正常失败反馈，没有增加逐技能网络预检或新的条件快照协议。

## 验证

验证结果见[验证记录](verification.md)。历史的 349 个常规候选请求不代表全部技能的所有正负条件均通过，不将普通缺材料负例或未完成前置测试当作产品缺陷。
