# 技能条件真实客户端测试

测试日期：2026-10-26。接续[技能使用条件审计](README.md)，固定客户端 `mvo7nxvf`，真实 Chrome 客户端连接本机 Gateway 和 Renewal 服务端；并发使用独立普通玩家测试角色，没有启用无条件技能权限。本轮只测试和记录，不在中途修改产品代码或运行版本。

## 验证方法

- 覆盖 12 条主线的 13 棵职业树，诗人与舞娘分别测试。记录服务器当前下发的自动候选集合，不把静态树中的被动、未开放自动辅助或临时魂链技能当成普通候选。
- 通过原客户端技能发送入口发出真实目标／地面请求，记录角色、技能、目标、出包和服务器回执。直接发送有意缺条件的负例，不表示自动战斗调度会忽略面板条件。
- 成功必须有匹配施法者与技能的伤害、成功动作或明确地面放置回执；读条开始不算成功。地面放置不等于已经造成伤害。
- 允许已审核父子技能回执映射；拒绝必须读取 `ACK_TOUSESKILL.result` 与原因，不能仅凭包名。概率失败、冷却、目标无效和条件缺失分别记录。
- 对战斗设置提示检查三类：提示非空却实际成功、没有提示却被服务器拒绝、保持面板打开时条件变化后 DOM 是否更新。内存快照与 DOM 观察明确区分。
- 初期准备接口错误、循环对象记录失败和同地图目标被其他测试角色击杀均列为测试工具问题；不计产品失败。后续隔离地图，采用召唤结果返回的目标 ID，对未确认项目定向补测，保留已明确成功的证据。

## 范围边界

本轮不是 804 个不同技能逐个在所有条件组合下成功施放的证明。自动候选全量请求之外，仅对准备技能和关键条件做正负对照；被动技能没有施放动作，非自动主动技能未逐项覆盖。服务器明确拒绝也属于有效负例证据，但不能替代条件满足时的成功验证。

原始证据保存在 `work/skill-live-20261026/`，包含固定产物摘要、账号组权限、各组请求与回执、DOM、覆盖清单和清理核对。临时测试物品与角色改动只涉及专用角色，不使用用户正常游玩的角色。

## 战斗设置提示对照

本轮检查的不是仅能否发送技能，还对照技能选项中的不可用原因、实际服务器结果以及保持同一面板打开时的刷新。

- 武器／盾牌：无矛的连刺、无盾的盾击提示与服务器拒绝一致，补齐装备后有真实成功回执。
- 材料／弹药／召唤物：缺工具、缺箭、缺狼等提示有正负例；补齐工具后，已打开面板的“材料不足”自动消失。召狼、召鹰及女舞娘正确鞭与箭均记录成功回执。
- 冷却：冰晶波爆施放后显示“冷却中”，同一卡片 DOM 保持不变，冷却结束后文字自动消失。
- 特殊状态：能量外套期间 Psychic Stream 的不可用提示与服务器拒绝一致；无该状态时有成功证据。巅峰使技能转为增益的文字属于自动策略提示，手动成功不应算作错误禁用。

### 确认的缺口

1. **动态技能列表不刷新**：真实获得猎人之魂后，服务器与运行时技能集合新增 499 动物猛击，但已打开战斗设置没有新增该卡片；关闭重开才出现。现有定时刷新只更新已有卡片，不能覆盖新增技能。
2. **目标标记没有完整预判**：龙骑士剑气－魅影对无本人标记的目标无提示，服务器明确拒绝；审判者第二击在施法者信仰状态成立、目标没有所需烙印时仍无提示并拒绝。后者已对照服务端目标烙印检查，不按概率失败处理。
3. **动态场地与材料豁免仍有边界**：无水地形的水球术、缺宝石的部分技能存在无提示但服务器拒绝。宝石免耗等服务端例外未完整下发，不能简单把缺宝石一律禁用。

以上是本轮记录，尚未进行新一轮产品修复。无提示不等于在任意目标、地形和状态下均可施放。

- 三组测试和辅助账号的浏览器均已退出。5 个专用角色离线恢复物品、Zeny 和地图坐标并逐项核对；武斗、女舞娘和灵魂辅助角色的原技能表亦精确恢复。魔法与生产／远程男角色缺少首轮操作前的原始技能表，只能确认恢复原职业并按该职业学满，不能宣称其最初技能点分配原样恢复。用户正常使用的 happyro 角色未参与这些职业切换。
