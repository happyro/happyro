# 服务端内容

服务端玩家可见文本直接维护在 `repos/happyro-server`。不通过旧分片或历史合并产物回写源码。

## 维护范围

| 位置 | 内容 |
| --- | --- |
| `npc/**/*.txt` | NPC 对话、菜单、公告 |
| `db/` | 物品、魔物、技能等数据库中的显示名 |
| `conf/msg_conf/` | 服务端系统消息 |
| `conf/motd.txt` 等 | 登录提示类文本 |

脚本标识、地图名代码、物品 ID、技能常量、控制流和英文脚本命令保持原样。只翻译玩家能看到的句子。

## 与客户端的分工

- NPC 显示名：Client `NpcNameTranslations.zh-CN.json` 与生成的 NPC 目录负责地图上的名称；对话正文在服务端脚本。
- 物品名称：运行时以 `itemInfo_true.lub` 和客户端目录为准；服务端 db 中文用于 Admin 和部分系统消息。
- 技能名称：Client 生成模块覆盖界面；服务端技能库是生成输入之一。

修改 NPC 脚本后，需要重新生成 NPC 目录，并检查冒险工具和 Admin 查询是否仍能匹配实例。生成入口见 [NPC](../game-data/npcs.md)。

## 校验

动态菜单还需检查 `setarray`、变量拼接、三元表达式和子程序参数，保留半角冒号、空选项、颜色码、格式占位符与导航参数。回归入口为 Server 的 `tests/test_dialogue_menu_localization.py`。

对话被硬拆成多行时，合并必须保留不同句子和刻意表演的换行，不能为了整齐把独立对白拼成一句。服务端编译和 `make server-verify` 只能证明进程起来，不能证明译文在游戏里显示正确；涉及对话或系统消息的改动需要进游戏核对。

## 副本名称与引用

副本创建、进入、名称变量、候选数组和 `ILI_NAME` 判断必须与 Renewal `db/re/instance_db.yml` 注册名一致；共用地图的 OnInstanceInit 分支也要核对，不能只修入口。回归入口为 Server 的 `tests/test_instance_names.py`。静态检查和实例创建抽样不代表完整任务通关。

### 仍需关注

- 时间花园两个次元监狱入口涉及完整副本接入，保持暂缓，不用文字修复冒充功能完成。
- 多人、战斗、长计时、完整长链和 EP18 连续通关未全面验收；旧夹具断言失败不直接等于产品缺陷。
- 氏族种子变化不等于已有数据库迁移。旧公会接力在途角色若缺少历史起始等级，需要上线前确定运营处理方式，不推断或修改真实角色数据。
- 正式发布针对最终源码执行加载、LUB 编译及语义校验；核对 NPC 目录、导航、公告图与运行资源哈希。旧隔离快照的通过结果不证明最终合并树或发行包通过。

详细调试产物位于 work/，不作为构建输入或继续执行指令；复用测试环境前重新核对实际进程、端口和数据归属。
