# 第 3 步：游戏名称应用结果

先提交第 1、2 步结果：`b5395601`，再处理本次应用。完全依据独立扫描决策，当前游戏脚本只用于匹配及确定修改前状态，不沿用旧 NPC 审核结论。

## 应用依据与范围

遍历全部 10,024 个位置组，按当前启用目录的地图、坐标匹配。应用条件：本地该位置只有一个 NPC，DVG 同位置只有一个记录，数值形象 ID 相同，建议中文名就是该 DVG 记录原文，客户端不会再次映射该名称，显示名与原内部名均在 50 字节限制内。

这验证的是 DVG 记录与当前本地实例的对应；不把 RO321 的同位置异名自动判成相同身份。名称只取网站原文，未自行翻译。RO321 单站且缺少可比较数值形象的候选保留，未凭坐标或图片标签猜测。

## 结果

- 已修改：3,759 个 NPC，涉及 346 份服务端脚本（首次 3,743 个，最终复核新增 16 个）。
- 已相同：1,115 组。
- 无相同形象证据，保留：1,339 组。
- 本地位置不存在：1,812 组。
- 缺中文决策：1,944 组。
- 本地同位置多身份：55 组。

以上覆盖全部 10,024 组。完整逐组结果见 [outcomes.json](outcomes.json)，原始匹配快照见 `candidates/`，精确修改前后及来源见 [changes.json](changes.json)。旧 `manifest.json` 是应用前的匹配统计，最终状态以 [result.json](result.json) 为准。

服务端采用已有的 `显示名称::内部名称` 语法，只更新显示字段，保留 `#` 后缀和原始内部名称；静态事件、duplicate、enable/disable 和传送引用继续使用原内部名称。后续复查发现动态调用及身份分支仍有读取显示名的情况，已修复为读取内部标识，详见[调用链复查](review/README.md)。没有添加旧版兼容机制。没有对普通剧情文本和对话正文做全局替换。

客户端根据服务器新显示名直接展示，未扩大通用名称翻译表，避免将一个地点的名称套到其他同名 NPC。重新生成客户端 NPC 实例／资源目录和 API NPC 目录；后台读取 API 目录，无需添加重复翻译表。4 条导航覆盖配置只更新由原始声明组成的目录 ID，地图、坐标、形象和导航 ID 不变。

`manifest.json` 与 `candidates/` 保存应用前的候选快照；当前最终结果以 `result.json`、`outcomes.json` 和最终复核记录为准，不能将候选快照中的 reviewing 状态当作当前进度。

第三轮审查已将目录导入本机 API 数据库并完整重建 PWA，确认 3338 提供新产物；未重启或热重载本机游戏服，不宣称服务端内存中的 NPC 脚本已更新。
