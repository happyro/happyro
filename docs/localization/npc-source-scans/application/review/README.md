# NPC 名称应用调用链复查

本次在名称应用后检查服务端调用、共享脚本、客户端显示、导航、API 和后台消费方，不重新采集网站详情，不沿用旧 NPC 审核结论。

## 修复内容

`strnpcinfo(0)` 返回显示名称，`strnpcinfo(1)` 返回去掉隐藏后缀的显示名称，`strnpcinfo(3)` 返回内部标识。保留内部标识并不足以保证读取显示名的脚本继续正常运行。

- 自身事件、隐藏和身份分支改读内部标识。包括共享诡异生物事件、彩色管道任务、卡片分离和硬币兑换。需要去除内部后缀的身份比较先按 `#` 拆分。
- 确认共享脚本所有启用实例原显示名一致后，将精确匹配自身原名称的 26,043 处对话标题改读当前显示名。普通剧情正文、其他说话者标题不做全局替换。
- 另外修复 7 处条件选取或空白声明涉及的自身标题。38 条调用调整记录包含中间修改及显示标题调整，不表示 38 个独立最终身份错误。

复查涉及 265 份脚本；逐条动作按每份最多 2,500 条拆分，见 [manifest.json](manifest.json) 和 `actions/`。这些动作是首次声明名称变更之后的有序补充。

## 多方调用核对

- 追踪 `duplicate()` 到共享脚本主体；额外检查共享函数、运行时名称/形象设置和内部事件引用。
- 目录中 13,432 个实例的内部标识、坐标、形象、方向、能力、可见性及导航属性保持一致；未匹配实例名称保持不变。
- 客户端 NPC 可用性和传送按地图、坐标和形象处理；服务端导航仍按原内部标识查找。
- 移动端对话读取实体显示名称；API 输出显示名称，后台使用中文名称或来源名称回退展示，不需要独立翻译表。
- 检索 2,709 份代码、配置及数据文件，未发现精确引用旧目录 ID 的残留，见 [id-audit.json](id-audit.json)。

## 验证边界

将提交前脚本依次应用名称声明修改、调用修复、自身标题修复，重建结果与当前文件逐字节一致。此核验取代首次应用阶段“所有非名称字节保持不变”的结论。原阶段结果保留在上级 verification.json 的 initialApplicationVerification 中。

回归覆盖 11 个共享事件 NPC、40 个彩色管道、卡片分离、兑换及对话标题不泄漏内部标识。名称/决策测试 21 项、目录/编码/身份测试 32 项通过。客户端检查、API 检查和文档构建结果记录在上级 verification.json。
