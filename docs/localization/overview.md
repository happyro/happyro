# 本地化概览

HappyRO 的中文不是一次性机器翻译结果，也不能保证全部玩家可见文本都已替换。项目优先完善玩家最常接触的界面、物品、技能、系统和城镇内容，并在运行中发现问题后回到真实维护源修复。

## 为什么不能整库交给模型

客户端和服务端文件数量大、结构复杂。单个文件可能有几千甚至上万行。直接整文件翻译速度慢，也容易漏翻、误改程序标识或破坏格式。项目早期合并翻译分片后，曾经出现进入游戏后人物只剩下头部模型的情况。之后做了大量修复，但仍可能只覆盖了最常见路径。

因此当前产品翻译直接修改对应应用仓库或版本化覆盖文件，不再把 `docs/translation/` 当作发布源向 Client / Server 回写。

## kRO 资源

kRO 中部分文字保存在 LUB 里，不能当普通文本编辑。流程是：把 Lua 5.0 / 5.1 字节码提取为结构化 JSON，翻译玩家可见字段，校验后按目标 ABI 回编译，再写入运行目录并核对哈希。

运行时还会遇到图片文字、特殊编码、被其他资源覆盖、以及只有进游戏才确认是否生效的内容。因此不能声称 100% 汉化。

## 生效原则

- 不修改官方 GRF。
- 散装中文走 Gateway 覆盖目录或本机 `data/`。
- 构建期能静态化的技能和导航不再运行时执行对应 LUB。
- 译文不授予服务器权限；传送、召唤、发放始终由 map-server 裁决。

客户端生效链见 [客户端资源](client-resources.md)。校验命令见 [校验](validation.md)。
