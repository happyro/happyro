## 为什么服务端有，冒险工具却没有

冒险工具物品列表与详情使用客户端范围查询，后台对该范围增加 `client_exists=true` 条件。服务端存在性并不是图鉴可见性的唯一依据；当前客户端目录的收录范围也会限制结果。

相关实现：

- [冒险工具物品接口](../../repos/happyro-api/internal/httpapi/adventure_catalog.go)：列表与详情使用 `client` 范围，发放检查账号权限。
- [物品目录查询](../../repos/happyro-api/internal/catalog/repository.go)：按当前客户端／服务端目录版本查询，并限制 `client_exists`。
- [物品目录视图构建](../../repos/happyro-api/internal/catalog/items.go)：分别记录客户端与服务端是否收录。
- [服务端发放实现](../../repos/happyro-server/src/map/game_control_item_grant.cpp)：检查物品是否存在且可用、数量、负重和背包空位；不按装备系列限制，宠物蛋不允许直接发放。
- [Renewal 装备定义](../../repos/happyro-server/db/re/item_db_equip.yml)：装备要求、基础属性与效果脚本。

因此，不能根据装备库定义承诺所有新装备都能在冒险工具发放；也不能根据图鉴搜索不到，反推该装备在服务端绝对不能使用。本次没有绕过图鉴去发放那些搜索不到的装备。

目录来源、生成与同步规则见[物品资料](items.md)。扩大收录范围时应同时核对名称、说明、图片、武器外观及实际效果，不能只取消查询过滤就宣布支持。

## 验证边界与后续检查

本次未验证精炼、评级、附魔、套装触发、技能伤害加成、自然掉落、NPC 兑换或副本获取途径，也未完成逐装备的三端显示检查。

若要确认某套装备可正式开放，应按以下顺序验证：

1. 核对服务端定义、当前目录快照和客户端资料是否一致。
2. 实测冒险工具搜索、详情、发放及背包显示。
3. 用满足等级和职业条件的角色穿戴，核对基础属性及外观。
4. 分别验证精炼／评级阈值、套装和技能效果。
5. 若面向正常游戏获取，再验证掉落、兑换和副本流程。
