# 候选翻译审计 Agent 规则

当前任务以 `work/candidate-audit.tsv` 为唯一认领清单。表头为：

```text
candidate_file	status	assigned_agent	note
```

## 认领工作单元

1. 开始前必须读取 `work/candidate-audit.tsv`，并确认目标文件存在。
2. 只能选择 `status=待处理` 且 `assigned_agent` 为空的行；不得选择 `进行中`、`已翻译`、`跳过` 或 `阻塞` 的行。
3. 认领时必须在同一次编辑中将该行改为 `进行中` 并填写自己的 agent 标识，然后保存；保存成功后才能开始翻译。不得认领已有其他 agent 标识的行。
4. 每个候选文件只能由一个 agent 处理。发现重复认领、路径不存在或候选表冲突时，停止该单元并在 `note` 说明，不覆盖其他 agent 的认领。

## 审计与翻译

1. `candidate_file` 是译文文件路径。对应源文件通过将路径中的 `chunks/translated/` 替换为 `chunks/source/` 得到；源文件是不可修改的核对材料。
2. 检查所有玩家可见的非中文文本，包括英文、韩文及其他语言；代码标识符、变量名、事件标签、NPC ID、数据库 ID、控制流、命令、占位符、颜色码和转义符必须保持不变。
3. NPC 唯一名、变量名、脚本标识符和玩家自定义角色名保持原样。玩家可见人名使用稳定中文名；已有项目或官方译名时沿用。
4. 不能把变量、函数名、地图名、内部协议字段、注释、脚本 ID 或已登记的虚构语言误判为待翻译文本。误报应标记为 `跳过`，并在 `note` 写明具体原因。
5. 必须直接修改候选表指定的译文文件，不修改源文件、其他 agent 的译文、正式源码或其他 agent 目录。译文应保持源文件的行数、缩进、结构和运行逻辑；不得用批量翻译、脚本生成或预生成译文代替人工判断。
6. 保留 JSON、HTML、脚本和配置结构；不得改变安全命令、任务条件、奖励逻辑或占位符含义。

## 完成与状态

1. 状态只允许使用：`待处理`、`进行中`、`已翻译`、`跳过`、`阻塞`。不使用 `已完成`、`待复核` 或其他状态。
2. 完成翻译并核对格式、行数和残留玩家可见外语后，将状态改为 `已翻译`，在 `note` 简述实际处理内容，并保留 `assigned_agent`。
3. 确认候选是误报、属于内部数据或属于设计上必须保留的虚构语言时，将状态改为 `跳过`，并在 `note` 说明判定依据。
4. 因文件缺失、结构损坏或无法安全翻译而无法继续时，将状态改为 `阻塞`，在 `note` 写明具体阻塞原因；不得用 `阻塞` 代替尚未完成的普通工作。
5. 每完成或跳过一个候选文件，立即保存译文（如有）、候选表状态和说明。必要时同步原 `manifest.tsv`、`translated-files.tsv`、`progress.md` 与 `terms-names.csv`，但不得伪造完成记录。
6. 候选表中的全部行处理完后，执行最终审计：不得有 `待处理` 或 `进行中` 行；逐项确认源/译文行数、脚本结构、玩家可见文本和状态记录一致。

## 并行协作与 Git

1. 多 agent 只能处理各自已认领的行；认领状态是锁，不得抢占或重写其他 agent 的工作。
2. 共享表发生冲突时保留先成功保存的认领，重新读取表后再选择其他 `待处理` 行。
3. 不执行 `git commit`、`git push`、`git reset` 或 `git checkout`。客户端资源、密钥、数据库数据、截图、测试输出和运行时文件不得加入候选译文。
