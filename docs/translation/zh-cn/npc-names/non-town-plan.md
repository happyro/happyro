# 非城镇 NPC 名称翻译计划

## 目标

在城镇 NPC 名称之外，逐批汉化玩家常用野外、地下城、岛屿、交通和任务区域中的可见 NPC 名称。优先处理进入频率高、位于新手成长路线或紧邻已完成城镇的地图，并保持悬停名称、名称牌、对话标题和导航文本使用一致译名。

本计划与城镇计划分开统计。完成一座城镇不自动代表其周边野外、地下城或副本已经完成。

## 范围边界

纳入：

- 野外地图中的 `script`、`shop`、`cashshop` 和 `duplicate` 可见实体。
- 地下城、岛屿、交通设施、任务专用地图和副本中的可见服务、剧情及引导 NPC。
- 由当前 Renewal 活动脚本实际加载，并会向客户端发送名称的 NPC。

排除：

- 魔物生成项、守护者和其他战斗单位；魔物名称由魔物名称表维护。
- `warp`、`mapflag`、函数、事件标签、隐藏触发器、测试 NPC 和已注释定义。
- 已纳入城镇批次的城区、室内、城堡、机场或任务地图，避免重复统计。
- 只存在于 Pre-Renewal、停用脚本或非当前 `scripts_main.conf` 入口中的定义。

## 优先级

| 优先级 | 区域 | 排序理由 |
| --- | --- | --- |
| P0 | 普隆德拉周边 `prt_fild00` 至 `prt_fild11` | 新手与日常移动频率最高，且紧邻已完成的普隆德拉城区。 |
| P1 | 吉芬、梦罗克、斐扬周边野外 | 核心六城成长路线的后续区域，地图边界明确、使用频率高。 |
| P2 | 第二阶段八城周边野外 | 衔接已完成的主要城市，按地图族逐城推进。 |
| P3 | 常用地下城、岛屿和交通地图 | 按实际进入频率拆分批次，不与野外进度混算。 |
| P4 | 低频任务专图、副本和活动区域 | 地图数量多、触发条件分散，在常用固定区域之后处理。 |

艾尔贝塔和依斯鲁得没有对应的 `alb_fild*`、`iz_fild*` 地图族。其相邻内容分别按沉船岛屿、海底洞穴等 P3 批次规划，不为保持城镇对称而虚构野外范围。

## 实施方式

每个批次按以下顺序执行：

1. 在批次文档中固定地图列表、排除项和活动脚本入口。
2. 从 `npc/re/scripts_main.conf` 递归展开当前活动脚本，提取目标地图上的可见 NPC 实例。
3. 去除 `#...` 实例后缀和 `::...` 事件别名，以英文基础名称建立全量清单，并人工复核可见性分类。
4. 优先复用 `terms-names.csv` 和已完成城镇译名；新名称写入按批次拆分的客户端显式名称表。
5. 为超过 23 个 ASCII 字符的名称建立封包截断别名，并检查截断冲突。
6. 增加清单数量、中文字符、代表名称、未知名称原样返回和截断覆盖测试。
7. 运行客户端全量测试和 PWA 构建；如修改服务端脚本，再运行服务端加载检查。
8. 实机只做代表性取样：每批至少检查入口附近 NPC，并按该批次类型补一个商店、任务或传送交互样本。

## 翻译规则

1. 沿用城镇 NPC 名称翻译规则，不修改脚本内部标识、事件标签、资源名和地图键。
2. 同名 NPC 在城镇与非城镇地图间默认使用同一译名；确有角色身份差异时，必须在术语表中说明。
3. 地名型名称使用项目既有中文地图术语；不根据英文逐词临时创造同义地名。
4. 告示牌、入口、传送点等可见名称按其实际功能翻译，不统一回退为“野外居民”或其他泛化名称。
5. 未进入当前批次清单的英文名称保持原样，以便覆盖检查发现遗漏。

## 批次完成条件

只有同时满足以下条件，批次才能标记为“已实现”：

1. 地图范围和排除项明确，不使用含糊的“周边地图”表述。
2. 当前活动脚本的玩家可见 NPC 清单已生成并完成人工分类。
3. 客户端显式名称表覆盖全部英文基础名称，自动检查缺失数为 0。
4. 所有超长名称通过 23 字符截断映射和冲突检查。
5. 客户端测试、构建及必要的服务端加载检查通过。
6. 完成与批次规模相称的简单实机取样，名称显示和代表性交互正常。

只确定地图范围时标记为“已排期”；只有部分常用 NPC 译文时标记为“翻译中”，不能据此标记整个地图族已实现。
