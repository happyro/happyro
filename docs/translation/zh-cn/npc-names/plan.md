# NPC 名称翻译计划

## 目标

统一 HappyRO 常用城镇中玩家可见 NPC 的中文名称，建立可复用的名称术语表，避免同一个 NPC 在名称、导航和任务文本中出现不同译名。

## 阶段

### 第一阶段：核心六城

- `prontera`：普隆德拉，约 308 个脚本声明
- `geffen`：吉芬，约 119 个脚本声明
- `morocc`：梦罗克，约 144 个脚本声明
- `payon`：斐扬，约 147 个脚本声明
- `alberta`：艾尔贝塔，约 137 个脚本声明
- `izlude`：依斯鲁得，约 125 个脚本声明

合计约 980 个声明，去除重复 NPC、隐藏脚本、商店和内部项后，实际名称数量会显著减少。

### 第二阶段：主要城市

扩展到 `aldebaran`、`yuno`、`comodo`、`rachel`、`veins`、`einbroch`、`lighthalzen`、`hugel` 等主要城市。

### 第三阶段：其他常用城镇

扩展到 `amatsu`、`louyang`、`gonryun`、`umbala`、`brasilis`、`dewata`、`malaya`、`moc_para01` 等地图。

## 翻译规则

1. 只翻译玩家可见名称，不修改脚本函数名、标签、资源名、地图键和内部标识。
2. `NPC名称#internal_id` 只翻译 `#` 前的显示名称，完整后缀必须保持不变。
3. 同一个英文名称必须优先使用统一译名；有官方或项目术语时以术语表为准。
4. 名称较长时检查客户端名称牌、导航结果和对话标题的显示宽度。
5. 重复 NPC 应按显示名称去重，但保留每个地图实例的完整脚本记录。

## 验收

- 服务端脚本编译通过。
- 目标地图中名称牌显示中文。
- NPC 可正常点击并进入对话、商店或传送功能。
- 导航搜索和任务文本未因名称变化失效。
- 同一名称在术语表、服务端脚本和客户端显示中一致。
