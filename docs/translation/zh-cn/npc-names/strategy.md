# NPC 名称翻译策略

## 目标

统一 HappyRO 城镇及常用非城镇区域中玩家可见 NPC 的中文名称，建立可复用的名称术语表，并保证悬停名称、名称牌、对话标题和导航文本使用一致译名。

本文件是范围、规则和验收标准的唯一来源；各批次的当前状态只记录在 [progress.md](progress.md)。

## 实施阶段

### 第一阶段 A：核心六城名称种子

先登记六城常用、公共和剧情入口 NPC，为后续逐城全量覆盖建立术语基础：

- `prontera`：普隆德拉
- `geffen`：吉芬
- `morocc`：梦罗克
- `payon`：斐扬
- `alberta`：艾尔贝塔
- `izlude`：依斯鲁得

这一阶段只代表“部分覆盖”，不能标记为整张地图已实现。

### 第一阶段 B：核心六城逐城全量覆盖

每次只处理一个城镇，明确主地图及关联室内地图，生成服务端活动 NPC 的完整英文基础名称清单，然后补齐客户端映射并完成实机验收。

第一阶段六城已完成该流程。

第二阶段八城的全量清单、客户端映射、自动检查和代表性实机取样均已完成。范围与证据见 [batches/towns/phase-2-towns.md](batches/towns/phase-2-towns.md)。

## 范围边界

纳入：

- 当前 Renewal 活动脚本实际加载的 `script`、`shop`、`cashshop` 和 `duplicate` 玩家可见实体。
- 城镇、野外、地下城、岛屿、交通设施、任务专用地图和副本中的可见服务、剧情及引导 NPC。

排除：

- 魔物生成项、战斗单位、`warp`、`mapflag`、函数、事件标签、隐藏触发器、测试 NPC 和已注释定义。
- 已纳入其他批次的地图，避免重复统计。
- 只存在于 Pre-Renewal、停用脚本或非当前 `scripts_main.conf` 入口中的定义。

艾尔贝塔和依斯鲁得没有对应的 `alb_fild*`、`iz_fild*` 地图族。其相邻内容按沉船岛屿、海底洞穴等独立批次规划，不虚构野外范围。

## 翻译规则

1. 只翻译玩家可见名称，不修改脚本函数名、标签、资源名、地图键和内部标识。
2. `NPC名称#internal_id` 只翻译 `#` 前的显示名称；`#...` 和 `::...` 必须保持不变。
3. 客户端名称表负责实体悬停名称和名称牌；服务端 `mes "[名称]"` 负责对话标题。两条来源都必须使用同一译名。
4. 不为解决客户端悬停英文而批量改写服务端 NPC 定义名，避免破坏 `duplicate()`、`enable/disable` 和事件引用。
5. 同一个英文名称优先使用统一译名；有官方或项目术语时以 `glossary/npc-name-terms.csv` 为准。
6. 英文名称超过 23 个字符时，必须验证 24 字节名称封包截断后的别名仍能命中译文。
7. 重复 NPC 按英文基础名称去重，但覆盖检查必须包含目标范围内的每个活动实例。

## 批次完成条件

只有同时满足以下条件，进度才能标记为“已实现”：

1. 批次文档列出地图范围和明确排除项。
2. 从服务端当前活动脚本生成全量 NPC 名称清单，并完成人工可见性分类。
3. 所有英文基础名称均能命中客户端中文名称表，自动检查缺失数为 0。
4. 所有超长英文名称均通过 23 字符截断映射检查，且不存在译名冲突。
5. 客户端构建和名称表测试通过；如修改服务端脚本，服务端构建也必须通过。
6. 按批次规模抽查悬停名称、名称牌、首次对话及多页对话标题。
7. NPC 对话、商店、传送、任务和导航功能未因名称处理失效。

只通过服务端构建、只登记术语表或只抽查少量常用 NPC，均不能标记为“已实现”。

## 实施流程

1. 在批次文档中固定地图列表、排除项和活动脚本入口。
2. 从 `npc/re/scripts_main.conf` 递归展开当前活动脚本，提取目标地图上的可见 NPC 实例。
3. 去除 `#...` 实例后缀和 `::...` 事件别名，以英文基础名称建立全量清单，并人工复核可见性分类。
4. 优先复用术语表和已完成批次译名；新名称写入客户端显式名称表。
5. 为超过 23 个字符的英文名称建立封包截断别名，并检查截断冲突。
6. 增加清单数量、中文字符、代表名称、未知名称原样返回和截断覆盖测试。
7. 运行客户端全量测试和 PWA 构建；如修改服务端脚本，再运行服务端加载检查。
8. 完成与批次规模相称的简单实机取样，至少覆盖名称显示和一个代表性交互。
