# HappyRO 变更日志

本目录按日期记录 HappyRO 自有的用户可见功能、汉化、修复、构建和维护流程变更，不逐条复制上游提交历史。记录范围从 2026-08-24 建立的 `zh-cn` 维护基线开始。

本目录集中汇总产品与工作区变化；各产品仓库仍保留与实际改动同提交的原始记录：

- `root`：工作区工具、部署和文档。
- `client`：`repos/happyro-client` Web 客户端。
- `server`：`repos/happyro-server` rAthena 服务端。
- `admin`：`repos/happyro-admin` 管理后台，原始记录位于其 `changelog/`。
- `api`：`repos/happyro-api` 独立 Go 后端，原始记录位于其 `changelog/`。
- `gateway`：`repos/happyro-gateway` 资源网关，新记录位于其 `changelog/`，旧记录保留在 `CHANGELOG.md`。

根仓库可汇总 Admin 与 Gateway 的用户可见变化；集中日志不能替代产品仓库内的记录。文档站的同步规则、导航与主题维护不另写产品日志。

## 维护规则

- 日期日志使用 `<年>/<月>/YYYY-MM-DD.md`，一级标题为日期，同日追加；索引按日期倒序。
- 二级分类依次为「新增、优化、修复、移除、部署与维护、验证与待办」，只保留有内容的分类。较长分类可用功能三级标题分组。
- 按实际变化分类，不仅按动词判断：补译既有内容属于修复，首次开放功能属于新增，流程或布局调整属于优化。
- 每条记录以行内代码格式的 `[scope]` 开头；作用域只使用仓库名 `root`、`client`、`server`、`admin`、`api`、`gateway`，跨仓库按此顺序用 `/` 连接，例如 `[root/client/server]`。工具、翻译源、部署和工作区文档属于 `root`。
- 标题与正文、列表与其他段落之间保留一个空行；连续单段列表项之间不留空行，使用紧凑列表；文件以一个换行结尾；一条聚焦一个变化，写清结果与必要的约束。
- 测试、运行验收及未完成事项放入「验证与待办」。详细证据放专题文档；不把编译通过、模拟验收、真机验收、安装和发布混为一谈。
- 日期日志描述当日状态。同日反复调整可合并为当日最终行为，但必须保留验证边界与未完成事项；完整过程可追溯 Git 历史，不另存多份原文。
- 章节链接使用当前 Markdown 标题自动生成的锚点，不保留旧标题锚点或添加兼容 HTML。
- 尚未提交的新修改标记为“未提交”，提交时移除。历史记录格式整理不逐条添加此标记。

### 日期日志示例

```markdown
# 2026-10-12

## 新增

- `[client]` 支持游戏内横竖屏切换。

## 修复

- `[client/server]` 修复长中文 NPC 名称显示乱码的问题。

## 验证与待办

- `[client]` 移动端拾取设置仍待真机复验。
```

### 检查与同步

根仓库是唯一内容源，文档站不独立改写正文。在根仓库执行：

```bash
python3 tools/changelog/manage.py check
python3 tools/changelog/manage.py sync
```

`check` 只读检查格式、根索引、文档正文及侧栏；`sync` 先验证根日志，再复制日期及版本页面并生成文档站侧栏，不复制原文归档、不删除额外页面。无参数仅显示帮助，支持 `--no-color`。发布说明不套用日期日志的分类与作用域规则。

同步后在文档仓库运行 `npm run docs:build`，并对两仓库运行 `git diff --check`。
